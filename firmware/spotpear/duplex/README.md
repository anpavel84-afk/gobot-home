# Непрерывный разговор Spotpear через PLAN

Задача владельца — GitHub issue #2. ESP-SR закреплён на 2.4.7. На ES8311 принимаются два I2S-слота: MIC и цифровой DAC reference. Вызов штатного FD AFE использует MR при 16 кГц после ресемплера 24 кГц. Передача на динамик дублирует mono PCM в два TX-слота. microWakeWord получает только MIC. В standby PCM обрабатывается локально. Микрофон в активной C-сессии работает одновременно с воспроизведением. TurnGuard сохраняет транспортный lifecycle, но отключает локальный submit по 800 мс тишины после серверного согласования continuous. Предел сессии и закрытие остаются у Brain.

## Бесплатный аппаратный тест

prepare_duplex.py накладывается на копию проверенного MWW-дерева 0.3.0. Команда GOBOT_DUPLEX_CHECK подготавливает следующий tap к локальной проверке. GOBOT_DUPLEX_BEGIN запускает ту же бесплатную диагностику через USB, поэтому не считается проверкой физического касания. Синтезированный локально сигнал длится восемь секунд. После трёх секунд хвоста плата освобождает обработку, очищает очереди и возвращает local wake. Ни PCM, ни речь не сохраняются. Из USB читаются только числовые показатели. Мощность MIC и выхода AFE помогает сравнить прогоны. Её отношение без контролируемой акустики не объявляется ERLE или доказательством сохранности слов человека.

Владелец подтвердил речь поверх тестового звука. В evidence.json приведены счётчики физической платы. Проверка текста «Подожди, а завтра?» через модель имеет отдельный результат.

## LiveKit на PLAN

Нативный ESP32 SDK 0.3.12 зависит от esp_capture ~0.7 и av_render ~0.9.1. Эти версии требуют ESP-SR 2.1.5, esp_codec_dev ~1.4, esp_audio_codec ~2.3.0, esp_audio_effects ~1.1.0 и esp_video ^1.0. Проверенная ветка GoBot использует соответственно ESP-SR 2.4.7, ~1.6.2, ~2.5.0, ~1.3.0 и ^2.4.1. Исходные ошибки сохранены на сборочном сервере. Для интеграции выбран предусмотренный владельцем путь 2B.

Локальный LiveKit Server 1.13.11 использует loopback 127.0.0.1:17880, RTC TCP 17881 и UDP 17882. Ключи и конфиг находятся в owner-private data/hardware/gobot-v1/livekit/. Создаются два ограниченных участника в случайной комнате конкретной активации. Короткие JWT разрешают audio publish/subscribe, data publishing выключен. Один участник представляет устройство, второй — медиавход/выход существующего адаптера GoBot Brain. AudioSource очереди ограничены 100 мс, приём — 25 кадрами по 20 мс. Переполнение завершает операцию. После Close уничтожаются участники и дорожки. Запись комнат и reconnect с повторным запуском модели не включены.

На Python нужно установить services/voice/requirements-livekit.txt в существующее окружение. Опция private gateway continuous_live=true выбирает медиарелей. В режиме duplex_test через него передаётся локальный синтетический звук без модели. В режиме live_c используется тот же endpoint Brain /api/v1/live/sessions, с теми же ACL, guest scope, существующим client delegation, визуалами, инструментами и раздельным аппаратным бюджетом. Модель остаётся gpt-live-1. Клиент не вызывает StreamingSpeech.finish по паузе и не ждёт окончания микрофона для первого ответа. Activity используется для общего idle, PCM не фильтруется по громкости.

prepare_continuous.py накладывается на 0.4.0 и готовит 0.4.1. На PLAN guarded flasher имеет действия duplex/duplex-rollback и continuous/continuous-rollback. Проверяет оба заводских backup, текущий полный snapshot, исходный app, assets и разделы. Записывает только ota_0. Дамп с NVS остаётся приватным.

## Проверки

Loopback-тест tests/test_spotpear_livekit.py запускается при явном GOBOT_LOCAL_LIVEKIT_TEST, указывающем приватный конфиг локального сервера. Он проверяет двустороннее медиа реальных участников. tests/test_spotpear_live_media.py проверяет непрерывный микрофон и ответ через реальный LiveKit и два WebRTC peer с фиктивным Brain. Эти проверки не являются акустической или платной приёмкой.

Перед обновлением процесса gateway убедиться в active=false. Перед обновлением Brain проверить active_sessions=0 для C и B. Аппаратные grants добавлять новым grant_id, прежние usage не стирать. Разрешённый 12 ноября новый smoke — две сессии до 60 секунд, до 120 секунд суммарно, без backend Luna, CLI и Image API, оценка $0.10. Разговорные платные проверки разрешены только после записи этого допуска в существующую policy.

USB-чтение длинного дампа на этом ПК несколько раз прерывалось. Сохранены завершённые блоки. Продолжение разрешено только из owner-private before.bin с выравниванием 64 КиБ. Неизменённый хвост factory может быть включён в полный снимок после совпадения MD5, вычисленного самим чипом по текущей flash. Перед записью дополнительно сверяются действующий app и защищённые области. Использованный путь не записывает NVS, assets или неактивный OTA.

0.4.2-dev-session-ack добавляет подтверждение с платы перед запуском платного leg. Сначала применяются continuous и транспортные флаги, затем gateway получает gobot_session_ready. Отсутствие ACK запрещает provider launch. USB-команда GOBOT_MEDIA_BEGIN используется только операторским probe.py --media, который проверяет бесплатный duplex_test в локальном private config. Это не доказательство физического касания.

Три модельные пробы (3×15 секунд, оценка $0.0375) не дали слышимого ответа. Последняя показала hardware_input_backlog_or_state после 68 пакетов. Исправлены слишком короткий startup buffer и заполнение очередей служебной тишиной LiveKit до реального PCM. В continuous setup ограничен 10 секундами, RAM backlog — 12 секундами; это не запись до конца фразы. Mic pump ждёт запуска WebRTC sender. Ошибки содержат фазу и числовые counters, без речи.

Бесплатный duplex_test теперь проходит через production live_turn, WebRTC и LiveKit с локальным синтетическим peer и пятисекундной задержкой HTTP fixture. Весь HTTP перехвачен в процессе: никакого API/квоты. Физический прогон дал 248 uplink/147 downlink пакетов, 447 input frames, 400 во время звука, 0 ошибок и standby/upload=0. Backlog 5919 мс — измеренный эффект искусственно замедленного setup, не результат low-latency приёмки. Человеческое перебивание модели после ремонта остаётся непроверенным. Текущий gateway оставлен бесплатным; новый платный прогон требует отдельного аппаратного допуска.

Последующий Owner допуск — 50 ручных GPT-Live 1 запусков по минуте, без Luna/CLI/Image API/авторетрая. Это конечный пакет, а не безлимитное фоновое тестирование; счётчик хранится в прежнем ledger, даты и рестарты его не сбрасывают. Предыдущая одиночная модельная сессия дала playback ACK и подтверждённые 38 секунд, но владелец выполнил другой сценарий, поэтому human barge-in ещё не принят. После последней подачи PCM source в relay ограничен хвост Opus concealment: служебная тишина не должна бесконечно продлевать playback. Бесплатная проверка отдельно проверяет доставку отличающегося последнего 200-мс фрагмента и прекращение выходных кадров после источника.

## 0.4.3: capture после media-ready

Реальный пользователь подтвердил задержанное перебивание на 0.4.2. Gateway сохранил backlog 3879/3919 мс; сессия закончилась по согласованному 60-секундному пределу. Новый overlay prepare_media_ready.py применяется поверх ack-stage. Board сначала сообщает capture_deferred, Brain создаёт одну сессию, затем приложение получает gobot_media_ready и включает штатный AFE/Opus capture. На экране Connecting сменяется Listening только в этот момент. Ни RMS-порог для обрезки тихих слов, ни проигрывание всего вопроса после finish не добавлены. Wake-to-Brain остаётся false; this touch acceptance does not prove one-phrase wake+question.

Guarded install: `firmware/spotpear_bringup.py media-ready`; обратное действие `media-ready-rollback` проверяет новый source и возвращает сохранённый ACK app. Обязательные identity/security/backup/partition checks прежние, NVS/assets/другой OTA не записываются. Исправлена также ошибочная запись нескольких имён actions одним tuple-ключом в старых ветках выбора rollback; offline guard checks проходят, физический rollback не проверялся.

Установленный образ и SHA — media-ready-release.json. Бесплатный физический прогон через production adapter, WebRTC и LiveKit с 5 секундами setup дал 150/142 пакета, 400 кадров микрофона во время звука, peak backlog 120 мс, ошибок 0, phase=0/upload=0 после Close. Активация была USB, звук synthetic; это не новая human-touch/model/barge-in приёмка. Оставшийся пакет — 48 ручных минутных запусков. Следующая настоящая сессия записывается в отдельный согласованный DPAPI journal устройства; API-key/audio/embeddings/системные prompts не пишутся, личность телефона плате не присваивается.

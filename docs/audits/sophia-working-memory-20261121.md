# Sophia: рабочая память и параллельный контекст

Дата: 21 ноября 2026 года. Основание — прямое поручение владельца реализовать
выводы [аудита памяти](sophia-memory-20261121.md), включая поиск на каждый вопрос
и полезное дополнение уже начатого ответа. Состояние установки и числовые
результаты проверки публикуются в [CURRENT_STATUS](../CURRENT_STATUS.md) и
[evidence](../evidence/sophia-working-memory-20261121.json).

## Поведение разговора

В существующем Brain добавлена управляемая рабочая память для единственной
привязанной owner-terminal колонки. Перед первым ответом передаётся компактный
доступный контекст, а для каждого принятого вопроса запускается отдельный поиск
связанных реплик. Слово «помнишь» не является условием запуска. Поиск использует
локальный индекс слов с нормализацией русского текста и имеющиеся сводки;
он не открывает новый облачный запрос и не выполняет пользовательских действий.

Первый ответ не ждёт поиска. Контекст отправляется как недоверенные данные
приложения через штатный Realtime conversation.item.create. Отправка и запрос
ответа используют один writer lock: сервер различает контекст, доставленный
до запроса генерации, и контекст, появившийся после него. Получение подтверждает
настоящий conversation.item ACK. Быстрый контекст не ждёт ACK внутри того же
provider reader, который должен прочитать это подтверждение.

Уже произнесённый звук изменить невозможно. Поэтому полезный поздний результат
может вызвать **одно короткое продолжение того же вопроса после физического
окончания основного ответа**. Оно ограничено 384 выходными токенами, инструменты
отключены, действуют обычные допуски и учёт расходов. Поиск сам никогда не
создаёт ответ. Если промежуточный ответ инструмента уже использовал доставленный
контекст, третья реплика не запускается. При простом отсутствии нового
материала продолжение также не требуется.

Stop, новый вопрос, исправление входной реплики, смена транспорта или контекста
доступа делают прежний результат недействительным. Ожидание поиска после
воспроизведения вынесено из WebSocket command reader: Stop остаётся доступен,
пока поиск ещё работает. Время самого поиска ограничено двумя секундами;
окно ожидания после очень короткого первого ответа ограничено 3.5 секунды
от начала обработки вопроса.

## Срок хранения и восстановление

Для согласованной колонки подготовлена политика: **12 часов**, зашифрованное
восстановление включено, поиск, дополнения и смысловые сводки включены.
Из админки можно выбрать 1, 4, 12 или 24 часа. Это временная рабочая память;
у неё есть предел объёма — 128 обменов в одном контексте и 256 суммарно.
При заполнении вытесняются старые завершённые обмены. Обычные гости без
отдельной политики сохраняют прежнюю часовую RAM-память.

Контрольная копия хранится в новой таблице **существующей Brain SQLite**,
защищена Windows DPAPI и восстанавливается только после проверки того же
контекста и действующего разрешения. Нет резервной записи открытого текста
при ошибке шифрования. Истёкшие записи удаляются, изменение разрешения,
контекста профиля и явная очистка не позволяют восстановить старую копию.
Состояние сохранения и восстановления видно в админке.

Вопрос сохраняется и при прерывании ответа. Текст модели включается в replay
только при подтверждённом воспроизведении; усечённый, но услышанный ответ
отмечается как неполный. Прежний длинный ответ больше не обнуляет весь пакет:
ContextManager оставляет полезные ограниченные выдержки и указывает их
неполноту. Фоновый поиск исключает только полностью переданные источники.

Первичная установка не восстанавливает уже утраченные разговоры старого Brain.
Отладочный журнал не импортируется в память. Открытие личного архива,
автоматическое долговременное запоминание и смена семейной идентичности в
этот пакет не входят. Запросы к текущей доступной беседе не требуют PIN;
закрытый личный архив сохраняет прежнюю проверку доступа. При отсутствии
искомого фрагмента сообщается ограниченность доступного контекста, а не
утверждение «у меня вообще нет памяти».

## Смысловые блоки и расходы

Рабочий контекст содержит источники и, при наличии, структурированные блоки:
цели, условия, решения, открытые вопросы, сообщённые сведения. На каждые
четыре новых завершённых обмена может быть поставлена ограниченная задача
сжатия через Responses API с gpt-6-luna. Каждый блок обязан
содержать идентификаторы доступных источников и точную цитату. Числа,
отрицания и неопределённость проверяются; предположение ассистента нельзя
превратить в принятое пользователем решение или проверенный факт.

Один общий worker на Brain, очередь до восьми задач, один запрос одновременно,
до 1400 входных и 384 выходных токенов. Перед генерацией используется точный
provider count. Суммарное разрешённое расходование — **не более 2000 токенов
в сутки и не более 10% подтверждённых токенов основного разговора** для данного
контекста. Это ограничение токенов, не обещание фиксированного денежного счёта.
Действующий день проверяется повторно перед отправкой.

Все попытки, резервы и подтверждённый usage записываются в числовые таблицы
той же SQLite. Неизвестная стоимость остаётся зарезервированной; повторов
после ошибок нет. Старые owner/developer grants и usage не изменяются.
Отмена, очистка, истечение срока или устаревшая версия источников запрещают
применять позднюю сводку. Сводка по выдержке не удаляет прежние сведения
из непереданной части источника.

## Управление

[Админка памяти](https://plan.tailffc57c.ts.net/sophia/settings/#/privacy)
добавлена в существующий раздел приватности. Там доступны включение памяти,
срок, восстановление после перезапуска, поиск, дополнения, смысловые сводки
и отдельная очистка. Сохранение и очистка требуют свободной колонки;
изменение во время разговора отклоняется. Очистка также заменяет пустой
provider transport, чтобы прежняя история не оставалась на его стороне.

Brain API и owner panel проверяют точную привязку единственной активной
сессии; из панели нельзя подставить другой device/client/profile. Диагностика
передаёт счётчики и состояние, без реплик, сводок, source/scope/turn IDs
или ключей. Потерянный ответ на сохранение разрешается чтением состояния,
а не автоматическим повтором изменения.

## Проверка и границы подтверждения

Проверяется общий набор из 49 файлов: новая память, реальные локальные
ASGI/WebSocket соединения с mock provider, Stop при ожидающем поиске,
однократность продолжения, устаревшие результаты, повреждённая политика,
обычные инструменты, прежние native/board разговоры, очередь аудио,
прерывание, бюджеты, привязки, семейные ограничения и админка.
Отдельный Windows-тест использует настоящий DPAPI с синтетическими строками,
повторно открывает Memory и проверяет окончательную очистку.

Административный JavaScript проверяется DOM/state тестом. Визуальная
desktop/mobile проверка Chromium в облачном executor недоступна из-за
ограничения socket(); это не считается визуальной приёмкой. Разработческие
модельные ответы и платные акустические пробы не запускаются. Проверки
протокола и готовности физической колонки не являются живой оценкой того,
насколько естественно модель вспомнит конкретный разговор.

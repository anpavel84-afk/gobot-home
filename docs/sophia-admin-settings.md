# Рабочая панель настроек Софии

Эта панель подключается к существующему серверу PLAN и профилю физической
колонки Spotpear. Она продолжает принятый [дизайн центра настроек](design/sophia-admin-ui-20261120.md).
Фактическая установленная версия и результаты проверки находятся в
[CURRENT_STATUS.md](CURRENT_STATUS.md); наличие исходников не означает завершённое развёртывание.

## Адреса и доступ

- На самом PLAN: `http://127.0.0.1:18811/sophia/settings/`.
- С устройства владельца в существующей сети Tailscale:
  `https://plan.tailffc57c.ts.net/sophia/settings/`.
- Из прежней панели `/sophia`: ссылка «Настройки» в верхней части.

Это тот же loopback-сервер HOST-A на 18811. Действующий Tailscale Serve
завершает HTTPS и передаёт запросы на него. Отдельный публичный сервер,
Funnel, правила firewall и новый Brain для панели не нужны.

Для удалённого доступа проверяется личность, которую Tailscale Serve
вставляет в `Tailscale-User-Login`, и её соответствие сохранённому владельцу.
Установщик получает существующего владельца PLAN из локального Tailscale;
в `data/sophia-admin-owner.json` сохраняется только SHA-256 login и явное
разрешение локального интерфейса. Login, Tailscale auth keys и ключи моделей
не включаются в исходники или ответы API. Для этой границы обязательны
`127.0.0.1`, `proxy_headers=False`, точные Host/Origin и неизменённый Serve.
Локальный доступ доверяет оператору компьютера, он не является отдельной
проверкой Windows-сессии. Гостевой cookie голосового браузера не даёт прав
администратора. Чужой пользователь Tailscale и узел без user identity
не получают доступ к этой панели.

## Что можно настроить

| Действие | Область и фактическое поведение |
| --- | --- |
| Домашний город | Поиск существующим WeatherClient, выбор результата, проверка источника, просмотр разницы, запись в существующий профиль Spotpear |
| Погода включена | Отключение сохраняет место; повторное включение требует свежей проверки источника |
| Погодный сервис | Сейчас только реализованный Open-Meteo; Weather.com/OpenWeather показаны как неподключённые адаптеры |
| Режим разговора | Существующий режим fast/expert для следующего обращения, через имеющийся управляющий маршрут |
| Остановить ответ / микрофон | Существующие немедленные команды выбранной колонки |
| История | Серверные успешные изменения с прежними и новыми значениями; возврат места также требует выбора и проверки |

Остальные поля из принятого макета видны с пояснением «Пока не редактируется».
Громкость, яркость, постоянные единицы измерения, отдельная временная зона
часов, подключение календарей/умного дома и новые погодные провайдеры не
изображены применёнными настройками. Голос marin и основа пробуждения
Sophia V4 не изменяются через эту версию панели. Выбор режима эксперта
сам по себе не отправляет экспертное задание.

Панель не возвращает двухчасовые окна, финансовые/общие количественные
ограничения проекта и не обнуляет учёт. Числа берутся из существующего
budget status; оценка ответов и ещё не подтверждённая стоимость распознавания
подписаны отдельно. Открытие, переключение разделов и обновление состояния
не запускают разговор, CLI, озвучивание или изображение.

## Сохранение и подтверждение применения

Браузер не выбирает device ID, owner scope, координаты или URL провайдера.
Сервер определяет единственный существующий профиль по конфигурации
зачисленной колонки. GET использует SQLite read-only и никогда не создаёт
отсутствующий профиль.

Новый город представлен короткоживущим серверным кандидатом. Проверка
привязывается к владельцу, цели, ревизии и кандидату; предыдущий успешный
результат отзывается после новой неуспешной проверки. Перед записью сверяется
`expected_revision`. Одновременное изменение другой вкладкой требует нового
сравнения. Уникальный `operation_id` не позволяет повторить успешную запись
при потерянном HTTP-ответе, в том числе после перезапуска сервера.

Профиль и запись истории фиксируются одной транзакцией существующего
`data/browser-devices/profiles.sqlite`. Таблица `sophia_admin_operations`
создаётся только при реальном изменении; это журнал операций настройки,
не вторая база профилей или расходов. Запись с неизменными значениями не
меняет БД. Ни история, ни API настроек не выдают координаты и секреты.

Погодный инструмент заново читает профиль при следующем запросе. Для
открытого голосового сеанса есть отдельное обновление подсказки о домашнем
городе: проверка раз в две секунды только в безопасном ожидании, затем
`session.update` только с инструкциями. Ни аудиоконфигурация, ни соединение,
ни история диалога не сбрасываются. Применение подсказки подтверждается
точным ответом текущего provider socket и совпадением ревизии.

Панель сравнивает ожидаемую ревизию сохранённого места с
`lifecycle.home_context.applied_revision`. Это подтверждение серверного
голосового контекста, а не озвучивания или показа на LCD. При отсутствии
ACK состояние остаётся неподтверждённым; бесконечного повтора нет.
Обычный wake с неизменённым городом не получает дополнительных проверок.
При одновременной смене города и сетевом backpressure уже начавшаяся
служебная запись может удержать общий writer не более одной секунды;
ожидание её ACK не блокирует wake.

## API на существующем веб-сервере

Все методы ниже используют границу владельца. POST требует точного Origin.
Конфигурация и диагностические ответы имеют `Cache-Control: no-store`.

| Метод | Назначение |
| --- | --- |
| `GET /api/sophia/admin/snapshot` | Настройки, ревизия, история, безопасное состояние Brain/Gateway |
| `GET /api/sophia/admin/overview` | Тот же снимок |
| `GET /api/sophia/admin/settings` | Только существующий профиль и ревизия |
| `GET /api/sophia/admin/changes` | Успешные операции этой цели и владельца |
| `POST /api/sophia/admin/weather/locations` | `{query}` → короткоживущие кандидаты |
| `POST /api/sophia/admin/weather/verify` | `{candidate_id}` или `{}` для сохранённого места |
| `POST /api/sophia/admin/settings/validate` | `{expected_revision, patch:{weather:{...}}}` → разница |
| `POST /api/sophia/admin/settings/apply` | Тот же объект плюс `operation_id`; атомарная запись |
| `POST /api/sophia/admin/control` | Только существующие `mode`, `mute`, `stop` |

Свежесть Gateway проверяется по времени файла состояния: данные старше
15 секунд не становятся зелёной «связью» только из-за сохранённого флага.
Отсутствующие измерения не заменяются нулями. Точный DMA underrun пока
`not_instrumented`; это видно в диагностике. Старый код последней ошибки
показан как диагностический факт, а не самовольная блокировка здоровой связи.

## Проверка и откат

Новые тесты: [API](../tests/test_sophia_admin.py),
[доступ и mounting](../tests/test_sophia_admin_access.py),
[обращение «София» в погодном чтении](../tests/test_sophia_weather_addressing.py),
[обновление подсказки дома](../tests/test_sophia_home_refresh.py).
Существующие voice/lifecycle/weather тесты проходят с mock provider без
платных вызовов. Самостоятельный разбор обращения не расширяет голосовые
права на изменение города, таймеров или других данных.

Развёртывание требует отдельного native Windows gate на точном source SHA,
резервных копий WIP всех действующих worktree и SQLite через backup API,
проверки PID/времени создания/команд процессов и отсутствия активного
разговора. В отдельном CHECK проверяется возврат точных исходных файлов и
повторное применение, а копии БД проверяются на восстановимость.

Программный откат возвращает исходники и перезапускает только те же
проверенные процессы. Он не восстанавливает старые usage или профили поверх
новых пользовательских данных. Действие владельца после запуска сохраняется;
активный разговор или mute не являются основанием автоматически его прервать.
Прошивка, NVS, политика постоянного терминала и Tailscale Serve этим релизом
не меняются. Приватные backup/receipt остаются на PLAN, публичный паспорт
содержит только безопасные факты и хеши.

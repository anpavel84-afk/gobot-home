# GoBot Home vNext — целевая система и обновлённый стек

**Статус:** нормативная спецификация следующей реализации; готовность доказывается отдельно.  
**Объём:** web-first гибридный диспетчер, погодный помощник, таймеры, голосовая библиотека, рассказчик и контракты переноса на Spotpear.  
**Основа:** существующий Brain и текущие A/B/C. Никакого переписывания продукта с нуля.

## 1. Принцип продукта

GoBot сначала определяет задачу, затем выбирает подходящего исполнителя и форму ответа. Выбор модели не является первой и единственной операцией. Простые проверяемые действия обходятся без генеративной модели, но их STT/TTS и инфраструктура могут иметь стоимость. Утверждение «бесплатный таймер» означает отсутствие нового B/C/LLM-вызова, а не нулевую полную себестоимость.

Пользователь видит одну личность, общий разговор и согласованные экран/голос. Погода отвечает по данным, таймер — по состоянию инструмента, музыка — через реальный плеер, сказка — через генератор текста и проигрыватель, открытая беседа — через B/C, экспертная задача — через отдельный разрешённый адаптер.

## 2. Стек: сохранить и добавить

| Слой | Решение vNext | Не делать |
|---|---|---|
| Backend | Текущие Python/FastAPI/asyncio/Pydantic/SQLite и существующий venv/lockfile | Не обновлять Python и весь dependency tree ради этой задачи |
| Оркестрация | Модули внутри одного Brain: сценарии, планы, policy gate, единый исполнитель | Не создавать второй Brain/семейную БД/новую микросервисную платформу |
| Разбор | Существующие Quick Intents + типизированный реестр навыков; HassIL только после локального сравнительного spike | Не устанавливать весь Home Assistant; не матчить действия по подстроке |
| Семантический разбор | Опциональный интерфейс небольшого разборщика для 2–4 кандидатов; выключен без разрешённого исполнителя | Не добавлять LLM на каждый запрос, новые API-ключи или скрытый fallback |
| Речь | Существующие STT/TTS; отдельные provider adapters B и C; единый speech-style слой | Не считать одинаковое имя голоса гарантией одинакового звучания |
| Web | Существующий HTML/CSS/JS, круглый renderer, Web Audio и действующие capture/playback modules | Не заменять всё на React/Next и не создавать независимый демо-Brain |
| Данные | Действующие SQLite и ACL; временное состояние диалога в RAM при remember=false | Не писать весь разговор в новую SQLite таблицу без согласия |
| Погода | Существующий Open-Meteo adapter + нормализация, интерпретация, deterministic formatter | Не отдавать сырые значения модели как единственному владельцу смысла |
| Рассказчик | Ограниченный текстовый job, сегментный TTS, один плеер, подтверждённая позиция | Не держать Live ради непрерывного чтения; не генерировать безлимитно наперёд |
| ESP32 | XiaoZhi/ESP-IDF, ES8311, Opus, AEC, LCD и прошивка 0.4.3 как установленный эталон | Не менять аудиоформат и не прошивать устройство в ночном прогоне |
| Медиа C/B | Текущие LiveKit/aiortc/WebRTC и gateway остаются эталоном | Не совмещать новый роутер с заменой транспорта |
| Проверки | Существующий pytest и JS/браузерный harness; egress-deny для платных API | Не объявлять fixture реальным голосовым испытанием |

Версии зависимостей брать из фактического рабочего окружения и lockfile. Исторические номера в CURRENT_STATUS — свидетельства checkpoint, не команда установить их заново. Новую небольшую библиотеку добавлять только в изолированное окружение с pinned version, лицензией и тестами; при проблеме продолжать на имеющемся парсере.

## 3. Границы полномочий

### Разрешено автономно

Код, документация, типы, unit/integration tests, тестовые БД, браузерная автоматизация, статический анализ, использование существующих локальных аудиоактивов, ограниченная read-only проверка уже подключённой публичной погоды, сборка аппаратного кандидата. Публикация web preview на прежнем приватном HTTPS после проверок и при отсутствии активных обращений. Небольшие обратимые изменения в пределах GoBot, с backup и rollback.

### Не разрешено этим заданием

Автоматические оплачиваемые B/C/STT/TTS/LLM/Image-запросы; перенос ручного бюджета на разработчика; пяти­минутные сессии; неограниченное создание голосовых клипов; новые провайдеры; прямой Gemini API/Gemini CLI; изменение credentials, сетевых правил и других проектов; hardware flash/OTA/NVS; принудительный reset/force push; merge в master.

Существующая подписка рабочего coding-agent не является новым разрешением вызывать продуктовые модели из тестов или бесконечно порождать вложенных агентов. При лимите исполнителя сохранить checkpoint, а не переходить молча на дорогой сервис.

## 4. Модель состояний

Разделить три независимые сущности:

1. **Сценарий:** pending clarification, weather frame, timer frame, storyteller, conversation, expert job.
2. **Медиа:** idle, capturing, processing, playing, draining, muted, interrupted.
3. **Провайдер:** unopened, opening, active, closing, closed_confirmed, unconfirmed, quarantined_unconfirmed.

Смена картинки или сценария не закрывает provider session. `response.done`, получение последнего байта и `playback_finished` — разные события. Возврат микрофона зависит от реального playback/drain, актуального epoch и политики продолжения.

Один клиент владеет входным аудио, один renderer/player владеет выходом. Каждое событие содержит device/client scope, conversation_id, turn_id и playback_epoch. Поздний callback отменённого epoch не может снова включить микрофон или звук.

## 5. Каскад первичной маршрутизации

### 5.1. Активация

Касание/подтверждённая активация → ограниченная запись → действующий STT. Не запускать платную сессию на загрузке страницы. Не считать RMS доказательством личности, близости или адресованности речи. Локальный wake остаётся диагностическим до отдельной приёмки.

Аппаратный Stop и видимый web Stop действуют непосредственно на текущий аудиовыход; не ожидают распознавания или LLM.

### 5.2. Приоритеты после финального текста

0. Проверенные команды управления текущим взаимодействием. «Стоп» останавливает текущий вывод; «пауза» — активный плеер; «отмена» — текущую ожидающую операцию. Это не безусловная отмена всех таймеров, задач и сессий. Отрицания, цитаты и составная речь учитываются; «не останавливай» не есть Stop.
1. Ожидаемый слот/подтверждение принимается только при соответствии типу, актуальному pending_id, scope и TTL. «Который час?» после вопроса о длительности выходит в новый сценарий, а не считается плохой длительностью. Старый pending приостанавливается/отменяется по явной политике; позднее «да» не оживляет его.
2. Контекстные команды активного медиа: продолжить, повторить, тише. Если активных целей несколько — уточнить, не угадывать.
3. Полные детерминированные шаблоны и валидные эллипсисы LastActionFrame. Чтение контекста не исполняет действие.
4. Безопасный составной разбор и предварительный отбор кандидатов. Выполнение ещё запрещено.
5. Опциональный семантический разбор только неясного task-shaped запроса среди ограниченного числа навыков. Общее объяснение без необходимости инструмента минует этот шаг. Лексические маркеры — сигнал отбора, не доказательство команды. Косвенная просьба без маркеров может требовать уточнения; отсутствие маркера не гарантирует свободный вопрос.
6. Полный Policy Gate/Plan Validator: типы, права, scope, состояние интеграций, бюджет, актуальность и условия выполнения.
7. Исполнение → подтверждённый результат → речь/экран → обновление контекста.

### 5.3. Уже активные B/C

Не создавать второй STT и внешний предсессионный LLM поверх того же микрофона. Но **не удалять** проверенные native transcript/tool paths GoBot: у текущего C есть обработка бытовых команд по стабильному транскрипту, её нельзя потерять общим запретом «внешнего маршрутизатора». Все предложения действий — native tool call, transcript fallback, UI — сходятся в один Action Arbiter/Executor с общей дедупликацией.

B/C не выбираются заново на каждый вопрос. Вопрос о погоде внутри C остаётся инструментом общего Brain, ответ возвращается текущим каналом. Переход к длинному чтению — отдельная handover-транзакция, не запуск второго плеера.

## 6. Контекст и приватность

LastActionFrame — предлагаемый scoped объект поверх существующей контекстной логики, а не новая параллельная память. Хранить intent, проверенные slots, IDs результатов, domain, provenance, timezone и монотонное время истечения. TTL 60–90 с — стартовая настройка, не гарантия правильности и не глобальная константа. Scope включает household/owner, authenticated principal, profile_epoch, device и conversation.

«А завтра?» меняет период только в подходящем погодном frame; «а в другом городе?» — место. Смена темы, профиля, истечение TTL и удаление контекста не допускают старой привязки. Несколько подходящих frames → уточнение. Временной TTL не заменяет смысловую совместимость.

«Ещё пять минут» не обязательно новый таймер и не обязательно изменение старого. При неоднозначности уточнить. «Нет, на десять» после реально созданного таймера требует отдельной поддерживаемой операции изменения, а не скрытого создания второго.

При remember=false текст/сводки/история/персонализированная сказка остаются временными. Постоянно сохраняются только необходимые операционные факты разрешённых инструментов и ledger по существующей политике. Debug-журнал имеет отдельный opt-in/retention и не является памятью. Никаких транскриптов и домашнего аудио в публичных артефактах.

Пользовательская история, текст сказки и результаты инструментов никогда не подмешиваются к доверенным `instructions`. В handover они передаются отдельными полями/элементами по контракту конкретного provider adapter. Неподтверждённые модельные ответы не становятся достоверными фактами.

## 7. Составные запросы и идемпотентность

Запрещён `split` по каждому «и/затем/плюс». Союзы бывают в названии песни/сказки, перечислении объектов, числе, цитате, условии, объяснении и отрицании. Сначала строится ограниченный план с source spans; вся исходная фраза должна быть учтена, без проигнорированного опасного хвоста.

Для ночного MVP поддержать ограниченные явно независимые комбинации до двух действий и tool + open question/story. До побочных эффектов проверяются **все** части: типы, доступность, права и последовательность. При неизвестной/условной/неоднозначной части не исполнять «понятную половину» молча — уточнить либо предложить явно частичное выполнение. Например, «поставь таймер, только если…» не запускает таймер до проверки условия.

После полного preflight допустим план: выполнить таймер, зафиксировать result, передать разговорному сценарию только остаток вопроса с достоверной отметкой выполненного. Если второй сервис отказал во время исполнения, сообщить частичный результат. Внешние действия не образуют общую ACID-транзакцию; не обещать откат уже включённого устройства. Новое повторное обращение пользователя — новая операция, не дубликат по одинаковому тексту.

Стабильный idempotency key привязывать к server-issued operation_id, plan_id/action_id, scope и profile_epoch; provider call IDs выступают alias одной логической операции. Hash канонических параметров проверяет совпадение payload, но **не является единственной идентичностью действия**. «Поставь два одинаковых таймера» создаёт два action_id; повтор доставки одного action_id создаёт один результат. Совпавший ключ с другим payload → конфликт. Повторные tool calls одного turn не создают новые операции без связи с исходным намерением.

Для локальных таймеров использовать существующую транзакционную защиту/unique keys. Для внешнего API с неизвестным результатом пометить unknown и согласовать состояние; не заявлять exactly-once, если провайдер не поддерживает его.

## 8. Контракты

Реализовать Pydantic/JSON Schema по существующим соглашениям проекта. Нижеследующее — нормативные поля, не доверенные поля входного HTTP-запроса.

**SkillManifest:** skill_id, version, category, implementation_status, templates, typed parameter schema, allowed context, side_effect_class, permissions, requires_confirmation, provider dependencies, cost components, response templates, capabilities и tests. Нельзя объявлять timer.pause или smart-home executor готовым только из-за перечисления в enum. Runtime capability_status и ACL проверяются раздельно.

**IntentCandidate:** matched_by, skill_id, spans, proposed_args, missing_slots, ambiguity, contextual provenance. Модель не заполняет APPROVED и не выдаёт себе бюджет.

**RouteDecision:** schema_version, decision_id, utterance/turn IDs, scoped plan, route_type, validated actions, trusted policy result, response specification, handover descriptor. Route types: EXECUTE_TOOL, MEDIA_CONTROL, START_STORYTELLER, OPEN_CONVERSATION_B, OPEN_CONVERSATION_C, DELEGATE_EXPERT_A, CLARIFY_SLOT, ABSTAIN_UNAVAILABLE, NO_ACTION. Стоимость действия, STT, TTS и провайдера учитывается раздельно; `FREE_LOCAL` не описывает полную цепочку.

**ActionResult:** operation/action IDs, status(success/failed/unknown/not_run), verified data, evidence/provenance, state version, timestamp и safe error code. Подтверждение успеха нельзя рендерить до success. Fixture result отдельно маркирован и никогда не выдаётся в production как настоящий.

**AnswerEnvelope:** canonical facts, speech_text, display_data, source/validity, voice/style profile, response template ID, optional clip key, provenance и presentation epoch. Speech/display могут различаться округлением, но не фактическим смыслом.

**PlaybackAck:** client_id, stream_id, segment_id, epoch, event(started/drained/interrupted), actual played position, position precision и clock domain. Сервер не принимает ACK от чужого клиента. Отсутствующий/устаревший ACK не равен завершению звука.

## 9. Погодный помощник как эталон

### Данные

Переиспользовать текущий Open-Meteo, а не создавать второй источник. Нормализовать location identity, timezone, fetched_at, forecast interval/valid_at, units, nullable values, current/hourly/daily и source provenance. `0` отличается от `null`. API forecast/model value не называть собственным измерением датчика.

Даты «сегодня/завтра/суббота/выходные» вычисляются в часовом поясе запрошенного места, не по UTC серверу. Не терять место при «а завтра», не использовать старую дату после смены timezone. Ответы по прошлому/за горизонтом прогноза честно ограничить. HTTP retries при бесплатном read-only запросе ограничены и не запускают LLM fallback.

### Интерпретация

MVP: текущая краткая сводка, завтра/конкретный доступный день, выходные, смена места и возврат к домашнему, ближайшее окно ожидаемых осадков, практический ответ про зонтик при достаточных данных. Дневной максимум звучит как «днём до…», не как температура всего дня. Осадки за прошедший/будущий интервал не выдавать за «сейчас нет дождя». Вероятность дождя не превращать в факт. При недостатке hourly данных не выдумывать час начала.

«Пляж/купание» не получает гарантию безопасности по одной температуре. Сообщить доступные условия и предел вывода; течение/волны/качество воды не выдумывать. «Почему ты советуешь зонтик?» объясняет использованное правило без большой модели; общий вопрос о климате может перейти в разговор с отдельной проверкой источников.

### Речь и экран

Пример fixture `14.7 °C`: голос «около пятнадцати градусов», экран вправе показать 14,7 °C. На просьбу о точности сохранять десятичную величину. Выбрать явную политику округления, включая отрицательные/половинные значения, и покрыть её тестами; не полагаться на случайное Python banker rounding.

Подготовить числительные/склонения в контексте всей конструкции: «один градус», «два градуса», «пять градусов», «до пяти», «около одного», минусовые значения. `8 km/h` не превращать без правила в «ветра почти нет»: допустимо нейтрально произнести число. Субъективные «тепло/холодно» — только заданные правила/предпочтения, не случайная вариативность.

Сначала выбрать канонические факты, затем один из проверенных эквивалентных шаблонов. Вариативность не меняет уверенность и периоды. Нет обязательного LLM-перефразирования. В активном B/C тот же envelope используется как проверенный результат инструмента; отдельный TTS параллельно не стартует.

Погодный data-cache с актуальностью и audio-cache конкретного текста — независимы. Сначала проверить свежесть сведений, затем подобрать запись. Старый аудиофайл не становится источником погоды. Свежая сетевая погода и fixture-прогноз в интерфейсе различимы.

## 10. Голосовая библиотека

Сохранить существующие 100 marin-клипов и их происхождение. Инвентаризировать реальные файлы, хеши, формат, длительность, license/provenance и семантическое назначение. Не каждый filler подходит как подтверждение действия.

Каталог строится из сценариев: systemic, timer, weather, clarification, access/unavailable, media/story controls. Описать фиксированный текст, динамические slots, preconditions, result condition, voice profile, priority, interruptibility и cache scope. Цельные фразы предпочтительнее склейки отдельных слов. Частые комбинации можно pre-render, редкие — синтезировать по требованию.

Ключ включает точный/безопасно нормализованный spoken text, voice_id, provider/model/version, language, style, speed, speech-formatter version, audio format/sample rate и privacy scope. Нормализация не должна удалять минус, различать 1/1.0 неверно либо менять смысл. Персональные сведения не попадают в публичный/межсемейный кеш; remember=false не даёт права сохранять персонализированное аудио на диск.

В эту ночь сделать manifest, dry-run генератор и валидатор, dedup, ограничение размера/TTL, atomically published assets и fallback. **Массовый платный синтез не выполнять.** При cache miss использовать разрешённый текущий TTS только в ручном пользовательском ходе; иначе текст/экран и честная недоступность речи. Не включать системный голос браузера скрыто.

Filler не запускать автоматически через 300 мс и не блокировать им готовый ответ. Сохранить/адаптировать действующую ограниченную политику ожидания, отмену и приоритет реального аудио. Метрика содержательного ответа не включает filler.

## 11. Рассказчик

Отдельный исполнитель: выбранный/новый разрешённый текст → связные сегменты → существующий TTS → один проигрыватель. Режимы: готовый публичный материал, пользовательский текст, создание истории через уже разрешённую текстовую модель. Никаких новых моделей и скрытого перехода в экспертный CLI ради сказки.

Для бесплатной проверки подготовить короткую оригинальную тестовую историю в fixture namespace и явно тестовое аудио/существующий подходящий актив. Это доказывает работу player, не качество платной генерации/голоса. Production UI не подменяет произвольную просьбу одной заготовкой.

Ограничить input/output, длину сегмента, число сегментов наперёд и общий job budget. Pause не продолжает оплачиваемый синтез бесконечно. Stop отменяет queued work, освобождает плеер и блокирует late audio. Resume не открывает B/C, если человек просто просит читать дальше.

Позиция — по фактически подтверждённому playback. В браузере использовать события/played clock настоящего AudioContext/media элемента; на устройстве — только поддерживаемый endpoint ACK. Без точной позиции можно безопасно повторить последний подтверждённый сегмент, с обозначением coarse precision, но нельзя молча пропускать неуслышанный текст.

Для вопроса по сюжету передавать title, summary только услышанной части и последние подтверждённые услышанные сегменты. Не раскрывать будущие повороты из полной сводки. resume proposal из B/C проходит общий policy gate; старый output подавлен, lifecycle закрывается штатно. Если finalization C неизвестна, сохранять инцидент и запрещать новые расходы C; продолжение уже имеющегося локального аудио допускается после локального release и проверки единственного audio owner. Не делать provider ACK фиктивным условием вечной блокировки всего плеера.

## 12. Переходы B/C и контроль Listening

B: использовать актуальный контракт конкретного адаптера. Для документированного Realtime API текстовый пользовательский item и `response.create` возможны; запрос аудио — `output_modalities: ["audio"]`, транскрипт приходит отдельно. Не копировать `['audio','text']` из отзыва как универсально верный запрос. Зафиксировать contract tests без провайдера.

C: `session.input` для истории не объявлять гарантией немедленного голосового ответа. `response.create` нельзя использовать как Realtime trigger. Текстовый handover и replay исходного аудио — разные кандидаты, пока не приняты. Не выполнять платный replay ночью. RAM буфер bounded, отделён от live queue, имеет один consumption ID; не отправлять ту же первую реплику текстом и звуком без доказанной дедупликации. Ускоренная выгрузка Opus в realtime тракт не предполагается допустимой.

Если переход недоказан, web показывает точную ограниченность и доступный явный переход/текстовый ответ; не заявляет seamless PASS. Валидация handover-пакета не равна голосовой приёмке.

B полудуплекс: capture → processing → speaking → drain ACK → echo guard → bounded listening. Stop немедленно отменяет локальный вывод и инициирует provider cancel. No-speech 5 с и max utterance 15 с — начальные configurable bounds для теста, не критерии определения владельца. Deadline ожидания не продлевается бесконечно от фонового звука. После начала записи действует независимый абсолютный лимит. На предельной длительности не исполнять обрезанную команду как завершённую: пометить truncated и уточнить/предложить Tap-to-Finish. Не отправлять непрерывные обрывки ТВ в новые turns. Время/число turns/usage ограничивает исходный grant.

Tap в Listening завершает пользовательский ввод; Tap/Stop в Speaking останавливает вывод; защита от случайного касания и mute сохраняются. Глобальный mute не называется доказанным provider close.

## 13. C recovery остаётся отдельной подсистемой

`local_resources_released`, `provider_close_confirmed` и `final_usage` хранятся независимо. HTTP 503/404, истечение локального 60-секундного таймера и отсутствие звука не доказывают окончательное списание. Карантин не закрывает провайдерскую сессию.

Сохранить предыдущий ограниченный Owner grant и реализацию `032e4ea`, если они действительно есть. Не применять их повторно, не сбрасывать ledger, не расширять разрешение и не делать автоматических attach/reconnect проб. Night train разрабатывает не зависящий от C приборный контур; блокировка C не причина бросить погоду, таймеры и player. Итоговый отчёт отдельно показывает provider uncertainty и готовность web функций.

## 14. Флаги и выпуск

Новый режим server-side gated для Owner и конкретного web client. Предпочтительный URL `/device-next` на прежнем host/HTTPS; имя уточняется по фактической маршрутизации и попадает в отчёт. `ENABLE_PRE_SESSION_ROUTER` вводится как существующая policy/config extension, не публичный query-параметр обхода ACL. Для аппаратного client флаг OFF. `/device`, `/demo2`, текущие A/B/C и их настройка по умолчанию сохранены.

В owner preview может быть Hybrid/Direct B/Direct C только при фактических допусках. Выбор интерфейса не меняет grants. Production и fixture-mode явно разделены. Optional visual job не блокирует речь/таймер/закрытие.

## 15. Приёмка и ограничения обещаний

Нужны реальные исходники, тесты и интегрированная веб-страница, а не только схемы. Автотесты подтверждают логику/браузерный playback; акустика телефона/Spotpear и платные провайдеры остаются NOT_RUN до человека. Нулевые ошибки на наборе — результат этого набора, не математическая гарантия для всей речи.

Цели старой спецификации (например p50 1.5 с, p95 4 с до полезного звука) не выдавать за полученные. Отдельно измерять endpointing/STT/router/tool/provider/TTS/queue/playback; один согласованный clock domain. Ни один результат не улучшать включением filler в TTFA.

# Приёмка GoBot vNext — evidence вместо обещаний

## 1. Уровни доказательства

- **S0 static:** схема/manifest/source lint.
- **S1 unit fixture:** чистая логика на синтетических данных.
- **S2 integration local:** настоящий executor/HTTP/SQLite в изолированном тестовом scope, provider doubles.
- **S3 browser real-code:** настоящий JS и Web Audio/media callbacks через тестовый/private host; данные fixture либо read-only реальный инструмент обозначены.
- **S4 provider manual:** разрешённая человеком реальная платная сессия и usage. Ночной автопрогон этот уровень не выполняет.
- **S5 hardware/acoustic:** услышанная человеком речь, physical touch/ACK/шум и latency на конечном устройстве. Сборка и USB transport не заменяют S5.

В отчёте каждую способность снабдить уровнем, SHA, командой, exit code и ссылкой на артефакт. Нельзя повышать уровень из-за большого числа unit tests.

## 2. Базовый router dataset: минимум 150 кейсов

Сохранить JSONL по фактическим test conventions, например `tests/router_eval/cases.jsonl`:

| Группа | Количество | Что проверяется |
|---|---:|---|
| Прямые команды | 40 | Таймер, часы, погода, громкость, явный Stop |
| Контекстные продолжения | 25 | Слоты, отмена, погода, media resume, TTL/epoch |
| Составные фразы | 20 | Ограниченные планы, отрицания, цитаты, неизвестный хвост |
| Косвенные упоминания | 25 | Обсуждение команды не превращается в действие |
| Свободные вопросы | 20 | Нет лишнего semantic call или tool execution |
| Недоступные/запрещённые задачи | 20 | ACL, budget, offline, отсутствующая интеграция |

Не считать простую перестановку пунктуации 150 независимыми смыслами. Для набора определить gold decisions, допустимые альтернативы и forbidden actions. Добавить минимум 30 отдельных regression tests по concurrency/privacy/media, не подменяющих эти 150. Независимый reviewer готовит дополнительную holdout-выборку либо в отчёте указать её отсутствие. При генерации корпуса не использовать реальные семейные тексты.

Пример формата — не реализация движка:

```json
{
  "case_id": "timer_pending_escape_clock",
  "utterances": ["Который час?"],
  "context": {"pending_kind": "timer_duration", "profile_epoch": 7},
  "expected": {"route": "EXECUTE_TOOL", "skill": "clock.now"},
  "forbidden": ["timer.start", "paid_session.create"],
  "evidence_level": "S1"
}
```

| R30 | «Почему здесь такой климат?» | Отдельный conversational/external-verification route |
| R31 | Story paused → «Продолжай» | Resume player, без нового B/C |
| R32 | Нет story/media → «Продолжай» | Контекстный выбор/уточнение, не выдуманная история |
| R33 | Музыка и story одновременно заявлены active | Один audio owner/уточнение, не два плеера |
| R34 | «Стоп» при речи | Локальная остановка; не отменяет произвольно все таймеры |
| R35 | «Не останавливай сказку» | Не Stop |
| R36 | «Выключи люстру» при отсутствующей интеграции | Честный unavailable, без B/C как скрытого repair |
| R37 | «Кто придумал лампочку?» | Не включение/выключение света |
| R38 | «Что я говорил в личном разговоре?» от guest | ACL отказ до извлечения частных данных |
| R39 | C blocked, вопрос о погоде | Приборный путь работает без C |
| R40 | C blocked, открытый вопрос | Честный blocked либо только явно разрешённый fallback |
| R41 | Модель вернула APPROVED/новую роль | Не влияет на серверные права |
| R42 | Невалидный JSON semparser | Ни одного действия, controlled clarification |
| R43 | Пустая/неразборчивая транскрипция | Не создавать диалог/инструмент автоматически |
| R44 | Речь достигла max duration и обрезана | Truncated, не выполнение незавершённой команды |
| R45 | «Напомни выключить духовку через четверть часа» | Не управление духовкой; reminder только если исполнитель действительно есть |

Все приведённые ожидания проверяют смысл, не требуют буквального совпадения красивой фразы. Недоступный исполнителю навык должен оставаться unavailable даже при правильно распознанном intent.

## 4. Погода и речь

Проверить как минимум:

- current/hourly/daily, daylight и timezone; переход через полночь и DST в fixture timezone;
- «в субботу» и «на выходных» на границе недели, запрос за горизонтом прогноза;
- 14.7, -0.4, -0.5, -1, -2, -5, 1, 2, 5, 11, 21, 22, 25; просьба «точно»;
- фразы «около», «до», «от … до» и единицы °C/km/h/mm; отрицательный знак не теряется;
- null/NaN/missing против нуля; неполный forecast не заполняется фантазией;
- дневной максимум не объявляется постоянной температурой;
- вероятность осадков и сумма за интервал не смешаны;
- rain window без часов не получает придуманный час;
- 8 km/h не превращается в «ветра почти нет» без утверждённого правила;
- пляжный вопрос не даёт гарантии безопасности купания;
- HTTP timeout/429/битый JSON/устаревший кеш; нет дорогого fallback;
- identical audio text можно reuse только после нового подтверждения актуальности данных;
- speech/display отличаются допустимой точностью, но не периодом/местом/фактом;
- вариативные шаблоны сохраняют одинаковые canonical facts и uncertainty.

Read-only real-weather smoke по разрешённой существующей интеграции отделён от fixtures. Не тестировать коммерческие условия API новым платным контрактом этой ночью.

## 5. Медиа, контекст и сессии

- Отмена до первого звука, в середине сегмента и после его отправки, но до playback.
- Out-of-order/duplicate/stale/forged ACK, ACK другого client/epoch, потеря последнего ACK.
- `response.done` до конца playback: Listening ещё не открывается.
- Бесконечный шум после ответа: absolute followup/max utterance/session bounds не сбрасываются постоянно.
- Tap-to-Finish и Stop имеют разные действия по состоянию; mute не есть confirmed close.
- Browser background/pagehide/autoplay отказ не создаёт бесконечный разговор и не объявляет звук проигранным.
- Story pause/stop освобождает/ограничивает prefetch; новый job не получает позднее аудио старого.
- Resume повторяет безопасный coarse segment при недостаточной точности, не пропускает неуслышанный фрагмент.
- Story handover содержит только услышанное; дальнейший сюжет не утекает в summary.
- Один output owner при handover, таймерном сигнале, TTS и картинке. Визуал не блокирует voice close.
- Нет двойного STT в ACTIVE_B/C; native transcript fallback и model tool call не дублируют действие.
- User text/history/results не попадают в доверенные instructions.
- remember=false: RAM cleanup/epoch revocation и отсутствие новых постоянных приватных текстов/аудио.
- C local release не меняет final_usage; карантин не сбрасывает reserve/ledger.
- Новый route/flag и page refresh не потребляют одноразовое recovery grant.

## 6. Security / budget / runtime

API принимает пользовательский ввод, а не доверенный policy decision. Нельзя POST полей role=owner, budget=FREE_LOCAL или approved=true, чтобы получить действие. ACL действует на чтение frames/таймеров/истории, вызов tools и получение аудиоактивов. Public test fixtures не используют настоящие provider IDs и домашние координаты.

Paid-egress tests перехватывают provider client boundary и запрещают любые реальные create/transcribe/synthesize/generate calls в unattended suite. Проверить отсутствие calls через fallback, cache miss, reconnect и второй adapter. Утверждение «платных вызовов 0» подтверждается счётчиком/trace тестовой границы, не отсутствием API key в логах.

До/после deployment сравнить старые routes, auth, policy, feature flags и runtime. Backup/rollback не удаляет новые ledger записи или пользовательские изменения. Никакой автоматической очистки production DB ради зелёного теста.

## 7. Измерения

Отдельные spans: input end, endpointing, STT final, route start/end, policy, tool, provider setup, first text/audio, queued, first playback, drain, ready listening. Browser client interval измерять одним monotonic clock; не вычитать несинхронизированные часы устройства/сервера.

На малой выборке — n и отдельные результаты/медиана. p95 deterministic/router microbenchmark допустим при достаточной повторяемой выборке и явно описанном warm-up; это не p95 реальной речи. Не обещать <15 мс или «100% экономии» из внешнего отзыва. Записывать actual observed error rate, не глобальную гарантию.

## 8. Gate публикации

WEB_READY требует: реальные P0 функции через production code path, scoped auth, replay/negative tests, браузерный smoke, preserved old modes, отсутствие непредусмотренных paid calls и рабочий rollback. Missing paid-provider/manual acoustic acceptance отмечаются отдельно.

FIRMWARE_PREPARED требует: versioned contract, patch с compatibility map; FIRMWARE_BUILT дополнительно требует успешного build log и artifact hash. FIRMWARE_INSTALLED/HARDWARE_ACCEPTED запрещено ставить в этом ночном прогоне.

## 9. Минимальный утренний сценарий Owner

В итоговом отчёте дать точный открываемый URL и текущие условия ручного STT/TTS. Проверка без голоса возможна через text input и не должна требовать платной сессии:

1. «Поставь таймер на три минуты» → один настоящий таймер/виджет; повтор транспорта не создаёт второй.
2. «Какая погода завтра?» → «А в субботу?» → погодное продолжение без B/C, место/период понятны.
3. «Поставь таймер» → «Который час?» → часы вместо ошибки длительности; позднее «да» ничего не запускает.
4. Явно выбрать тестовую историю → pause/resume/Stop; test material обозначен. Отдельная просьба о новой истории не выдаёт fixture за генерацию.
5. «Не ставь таймер, объясни, что он делает» → ни одного нового таймера.
6. Открытый вопрос → выбранный действующий разговорный режим при разрешении или точный blocked status. Ни один лимит не сбрасывается.

Ручное сравнение настоящих B/C и акустики проводится Owner отдельно. Оно не входит в ночной автоматический PASS.

## 2. Что должно получиться

В существующем GoBot появляется новый приватный owner-only веб-режим устройства, предпочтительно `/device-next`, обслуживаемый тем же Brain. Старые `/device`, `/demo2`, A/B/C и аппаратный C сохраняются. Основной механизм:

`активация → действующий STT → контекст и строгие навыки → policy/plan validation → инструмент / рассказчик / разговор B или C / разрешённый эксперт → единые речь и экран`.

Не добавляй отдельную LLM перед каждым запросом. Не превращай Home Assistant в обязательное ядро. Не копируй KALO-прошивку. Не меняй LiveKit/аудиотранспорт одновременно с роутером.

Приоритет рабочего результата:

**P0:** owner web preview, настоящий детерминированный dispatcher, таймеры, погода, контекстные уточнения, безопасные действия/отказы, отсутствие непредусмотренных paid calls, сохранность исходного режима.

**P1:** каталог/кеш голоса, подключение существующих ручных STT/TTS/B/C paths, storyteller player и корректный handover/Stop. Нет бюджета — честно заблокированная provider часть, но остальной путь работает.

**P2:** ограниченные составные запросы, semparser interface, совместимость/сборка firmware candidate, расширение регрессий. Критические отрицания и отсутствие ложных действий — P0 независимо от уровня поддержки составных запросов.

## 3. Неприкосновенные ограничения

1. Один Brain, одна семейная модель и действующие ACL. При remember=false разговорный контекст и персональные истории временные; диагностический opt-in не считается согласием на память.
2. Ни одного автоматического платного разговора B/C, STT/TTS/model probe или массовой генерации клипов. Ручные grants Owner не переиспользуются для developer tests. Новые расходы не выводятся из слова «ночной».
3. Не увеличивать сессии до пяти минут, не сбрасывать ledger/counters, не повторять C recovery grant, не выдавать QUARANTINED_UNCONFIRMED за confirmed close. Сохранить неизвестный окончательный расход старой C-сессии.
4. Не добавлять провайдеры/API keys, Gemini CLI/прямой Gemini API, дорогие fallback, unbounded retry/subagents. Используй уже авторизованную coding-среду; отдельный Gemini-review не превращается в новый продуктовый API.
5. Не менять установленную 0.4.3, не прошивать/OTA/стирать NVS, не включать wake_to_brain. Разрешена подготовка отдельного патча и сборка кандидата.
6. Master не менять, PR оставить draft. Не изменять другие проекты, публичные listener, VPN/TLS/firewall и глобальный runtime.
7. Никаких claims «готово/работает/дешевле», основанных только на fixture, README или наличии поля в manifest.

## 4. Конкретная реализация

### Dispatcher и сценарии

Расширь существующие quick_intents/routing/context/tools вместо второй системы. Реестр навыков описывает схему параметров, готовность, зависимости, права, preconditions, результат, speech/display и тесты. Клиент и модель создают только предложения, одобрение выдаёт сервер.

Приоритеты: scoped Stop/отмена → валидный ожидаемый слот → активное медиа → полные команды и подходящие эллипсисы → ограниченный план → при необходимости 2–4 skill candidates для разрешённого лёгкого разборщика → policy gate → executor.

«Который час?» вместо ожидаемой длительности должно переключить задачу. «А завтра?» сохраняет погодное место/период только в актуальном scoped frame. «Да» без действующего pending ничего не разрешает. «Продолжай» имеет одну проверенную цель. Отрицание/цитата/обсуждение команды не исполняется.

Не дели фразы наивно по «и». До исполнения первого побочного эффекта проверь весь план. Для неясного хвоста/условия уточни. После подтверждённого действия передавай в B/C остаток запроса и result, а не повторное указание выполнить тот же инструмент.

Идемпотентность: server operation/action IDs, scope/epoch и payload consistency. Не склеивай два намеренно одинаковых таймера по hash аргументов. Не удаляй существующий native transcript fallback C: все каналы действий проходят через один arbiter, а не второй STT.

### Погода

Используй действующий Open-Meteo и собственный deterministic formatter: данные → интерпретация → canonical facts → speech/display. Реально подключи текущую погоду, завтра/день/выходные, смену места и короткие продолжения. Если данных для дождя/зонтика нет — не выдумывай.

`14.7` может стать «около пятнадцати» в речи, но экран и точный запрос сохраняют значение. Дневной максимум обозначается «днём до». Null не ноль; вероятность не факт; интервал осадков не текущая точечная погода. Относительная дата считается в timezone места. Склонения/округление/отрицательные значения покрыть тестами. Ответ о пляже не является гарантией купания.

### Voice Library

Сохрани и инвентаризируй уже существующие 100 клипов. Создай единый каталог связанный с навыками, compound cache key, ready/missing inventory, dry-run generator и validator. Сначала verified result, затем success clip. Погода обновляется независимо от кеша её озвучки. Персональные записи не делай общими. Нет генерации тысяч файлов за деньги этой ночью.

### Рассказчик

Сделай отдельный player с play/pause/resume/stop, segment IDs, bounded queue/prefetch, last-heard position и безопасной отменой. Подключи разрешённый существующий text/TTS adapter для ручного режима; при запрете он честно unavailable.

Бесплатно проверь player на оригинальной тестовой истории и явно тестовом локальном аудио. Не подменяй этим настоящий ответ на произвольную просьбу пользователя. Контекст вопроса по сюжету содержит только услышанную часть. Resume не запускает новый Live. Уточнение через B/C сохраняет место чтения и одного audio owner.

### Web и B/C

Новый режим использует существующие renderer/player/capture, круглый экран, таймер и погодные сцены. Добавь текстовый ввод для диагностики и доступности, не только микрофон. Понятные loading/offline/blocked/idle состояния; provider failure не блокирует часы/таймер/кешированный player.

Предсессионный router включён только в новом web client/owner scope. Устройство и старый direct B/C baseline не меняются. При уже открытом B/C нет второй фоновой STT-цепочки.

B: Realtime contract; аудиовыход `output_modalities:["audio"]`, транскрипт отдельными событиями; текстовый первый turn имеет отдельный contract test. C: не применять B-events как универсальный trigger; недоказанный handover остаётся gated.

Полудуплекс: real playback drain ACK → echo guard → listening. No-speech и max utterance ограничены абсолютным deadline, не продлеваются вечно от ТВ. RMS не подтверждает владельца. Truncated utterance не становится автоматически командой. Stop/Tap-to-Finish state-aware; stale callbacks не включают звук заново.

## 5. Как работать автономно

Выполняй W0–W8. Не проси уточнения по уже разрешённым обычным решениям. При новой опасной/платной/необратимой операции не расширяй права: пометь этот пункт BLOCKED и продолжай независимые части. Не завершай всю работу из-за C quarantine или отсутствующего платного допуска.

Один integration writer/deployer. Gemini может проверить diff read-only в отдельном worktree. Если его нет — сделай self-review и явно укажи это, не жди меня. Не запускай второй supervisor/runner/scheduler и не трать ночь на создание конвейера вместо продукта.

Каждый этап завершается кодом, тестами, evidence и небольшим commit. Исправляй introduced failures. Нельзя получить зелёный результат отключением security checks или заменой production executor mock-объектом.

## 6. Автоматическая проверка

Реализуй 150 базовых кейсов из ACCEPTANCE и дополнительные критические регрессии. Проверь production пути через тестовый host, а не только отдельно переписанный пример логики. Запрет paid-egress обязателен. Браузерная проверка должна вызывать настоящий JS/player и проходить реальный HTTP/auth маршрут в тестовом scope.

Реальные погодные read-only smoke допустимы ограниченно; нельзя публиковать домашние координаты. Любой fixture в UI помечен. Не считать тест STT mock доказательством распознавания русского, Web Audio playback доказательством слышимости на iPhone, а firmware build — акустической приёмкой.

## 7. Deployment и подготовка платы

Мне нужен утром конкретный открываемый web URL. После free checks разрешён ограниченный deployment только GoBot preview на существующем private HTTPS: backup, active_turns/media=0, single-writer lock, rollback, один контролируемый restart при необходимости. Не убивай живую сессию. Если безопасно опубликовать нельзя, не заявляй deployment: оставь tested build, причину и точную штатную команду запуска.

Подготовь минимальный backward-compatible аппаратный patch/контракт, проверь возможности старого ACK и собери candidate, если закреплённый build host доступен. Не прошивай. Не компенсируй отсутствующий playback ACK выдуманным подтверждением сервера.

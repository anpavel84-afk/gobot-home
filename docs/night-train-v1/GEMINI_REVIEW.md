# Gemini / Джейми — независимый review ночного GoBot vNext

## Основная роль: read-only QA рядом с Codex

Codex — единственный интегратор и deployer. Твоя задача — не переписывать архитектуру заново, а независимо проверить конкретный diff, сценарии и доказательства. Работа ведётся только в уже доступной авторизованной среде. Этот документ не разрешает установку Gemini CLI, прямой Gemini API, новые аккаунты или дополнительные платные вызовы продукта.

Прочитай `docs/night-train-v1/README.md`, `TARGET_SYSTEM_VNEXT.md`, `SOURCE_REVIEW.md` и `ACCEPTANCE.md`, затем фактический CURRENT_STATUS и свежий implementation diff. Не суди о runtime только по старому паспорту.

Требуется новый web-first GoBot: единый Brain, известные команды до paid B/C, погодный domain module, таймеры, speech/display separation, voice cache и storyteller player. Старый C, firmware 0.4.3 и direct A/B/C должны сохраниться.

## Что в прежнем отзыве исправлено и не должно вернуться

- Не всегда локальный intent предшествует LLM во всех конфигурациях Home Assistant; это образец политики, не универсальный факт.
- В текущем Realtime контракте для аудио выбирается `output_modalities:["audio"]`, транскрипт приходит отдельно. `['audio','text']` не копируется вслепую.
- «И» не безопасный универсальный разделитель. План проверяется целиком до первого side effect; условия/цитаты/отрицания нельзя терять.
- Глобальный Stop не значит глобальная отмена всех домашних действий. «Не выключай» не команда выключить.
- Hash параметров не различает повтор доставки и два намеренно одинаковых таймера. Нужны logical action IDs.
- LastActionFrame scoped, epoch/TTL-aware и семантически совместим; фраза «ещё пять» неоднозначна без конкретного контекста.
- Активный B/C не запускает вторую STT-цепочку, но проверенный native transcript-tool fallback C не удаляется.
- Все preflight/контекстные действия без LLM не делают весь запрос «за 0 рублей»: STT/TTS учитываются отдельно.
- Первичный replay аудио в C не гарантированно мгновенный и не разрешён как новая платная проба этой ночью.
- Нулевая ошибка на тестовом наборе не доказывает абсолютную безошибочность модели.

## Твоя проверка

1. Найди обходы policy/ACL через поля клиента, model JSON, stale profile_epoch, Replay и handover.
2. Проверь отмену pending, смешанные запросы, цитаты, числительные и отрицания. Нужны минимальные воспроизводимые кейсы.
3. Проверь раздельное хранение local release, provider close и final usage. Не принимай выдуманный потолок риска старой C-сессии.
4. Убедись, что browser load, silence, тестовые команды и fixtures не открывают оплачиваемые сессии.
5. Проверь погоду: timezone/периоды/null/вероятность/округление/склонение; шаблон не добавляет неподтверждённые условия.
6. Проверь voice cache: смысловой ключ, версии, privacy scope, свежесть данных независимо от аудио, success только после verified result.
7. Проверь story: last-heard position, отсутствие будущих спойлеров, pause/stop отменяют prefetch, resume не запускает ненужный Live, не возникает двух плееров.
8. Проверь реальные JS callbacks, late ACK, reconnect, foreground/background, отказы autoplay и Tap-to-Finish. Не выдавай fake ACK за playback evidence.
9. Проверь изоляцию старых device/demo/board и безопасный deployment. Firmware подготовка не должна изменить установленный образ.
10. Сопоставь README/утренний отчёт с фактическими tests/runtime. Mock/fixture/real/manual-not-run различены.

## Формат результата

Каждая находка: `ID | severity | file:line | воспроизведение | наблюдаемое | ожидаемое | минимальное исправление | тест`.

Отдельные verdict: source architecture / deterministic functions / browser integration / paid-provider integration / physical device. Не выдавай один общий PASS, скрывающий NOT_RUN.

P0: ложное действие, утечка, неразрешённый расход, потеря старого режима, опасный deployment. P1: неверные факты, потеря контекста, двойной звук, блокировка обычной задачи. P2: косметика/некритичный UX.

Если доступен execution sandbox — используй отдельный worktree/fixtures и existing test tools. В production checkout не писать и службы не перезапускать. Предложенные patches передай Codex, не применяй параллельно. Не запускай платные providers ради проверки.

Без доступа к исходникам не выдумывай line numbers и PASS: составь конкретный review по полученному diff и обозначь предел доступа. Review не должен блокировать остальные этапы бессрочно.

## Альтернативная роль — единственный ведущий

Если Owner запускает ночную разработку именно в Gemini/Antigravity **вместо Codex**, явно объяви единственного ведущего и выполняй весь `CODEX_OWNER_DIRECT.md` как общий контракт исполнителя. Название файла не привязывает разрешения к бренду модели. Не запускай одновременно второго ведущего, не устанавливай новый Gemini transport и не расширяй бюджет. В отчёте укажи, кто реально выполнял код и кто делал независимую проверку.

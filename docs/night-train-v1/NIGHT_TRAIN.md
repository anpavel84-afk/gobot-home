# Night Train v1 — исполнение без промежуточных согласований

## 0. Результат и автономность

Owner запускает исполнителя и не участвует в мелких согласованиях. Исполнитель проходит этапы ниже в одной реальной доступной рабочей сессии, устраняет локальные дефекты и публикует отчёт. Не заканчивать ответом «план готов» или «жду разрешения на каждый файл». Не обещать невидимую работу после завершения своей сессии.

Объём — законченный web-first vertical slice гибридного GoBot и подготовка аппаратного переноса. Не обещать завершённый серийный продукт за ночь. Если внешняя зависимость или бюджет не доступны, изолировать конкретную возможность, продолжать остальные задачи и честно указать предел готовности.

## 1. Правила рабочего дерева и параллельности

Один интегратор владеет PLAN runtime и рабочей интеграционной веткой. До любых действий прочитать AGENTS.md и действующие локальные instructions. Read-only инвентаризация: git status/HEAD, ветки/remotes, WIP, реально запущенные процессы/версии, текущие endpoints, активные turns/media и latest CURRENT_STATUS. Секреты не печатать.

Не использовать старый public SHA как команду reset. Проверить, есть ли локальный `032e4ea`, его потомки, незакоммиченные recovery/B changes. Сохранить WIP безопасным snapshot/patch/отдельной веткой, не удалять и не переименовывать их скрыто. Документационный пакет переносить docs-only коммитом/patch, не сливать старое дерево поверх нового runtime.

Создать отдельную implementation branch, например `codex/hybrid-web-vnext`; сохранить master и старый draft PR. Для независимого review использовать отдельный worktree или read-only GitHub. Второй агент не пишет в те же файлы, не применяет миграции и не перезапускает службы. Последовательная работа одного исполнителя допустима; новый supervisor не нужен.

Простой run-state JSON хранит phase, base/runtime SHA, branch, work completed, next command, blockers и evidence paths. Без токенов, семейных текстов и provider session IDs. Чекпойнт после каждого этапа позволяет продолжить реальному исполнителю, но не означает автоматического пробуждения чата.

## 2. Этапы

### W0 — фактическая база и страховка

- Проверить точные текущие A/B/C и firmware; не менять их ради маршрутизатора.
- Снять согласованный backup конфигурации и SQLite через штатный WAL-aware механизм. Проверить доступность исходного web bundle для возврата.
- Записать baseline тесты и известные failures до изменений. Не требовать нулевых ошибок чужой исторической ветки как оправдание бездействия; отделить introduced failures.
- Найти существующие routes/capture/player/router/tool/weather/formatter/cache modules. Создать карту «reuse / extend / new minimal module» с реальными путями.
- В тестах установить запрет внешних paid calls. Не читать секретные ключи для проверки доступности.
- Найти уже действующие grants по browser/board; не менять counters или TTL. Зафиксировать metadata без чувствительных идентификаторов.

**Выход:** baseline.json, rollback plan и безопасная implementation branch. W0 не превращать в бесконечный аудит всего проекта.

### W1 — контракты и реестр навыков

- Реализовать typed SkillManifest, IntentCandidate, RouteDecision, ActionResult, AnswerEnvelope и PlaybackAck либо расширить существующие эквиваленты.
- Добавить adapter поверх текущего catalogue/quick intents, не дублирующий сотни сценариев в новом несовместимом формате.
- Присвоить skills фактическую готовность: implemented / unavailable / experimental. Наличие manifest не включает устройство или инструмент.
- Ввести scoped context frame/pending lifecycle с типами, TTL и profile_epoch. Реиспользовать существующие topic/pending stores.
- Тесты целостности manifest и независимости policy от вывода модели/клиента.

**Выход:** работающий типизированный слой, связанный с текущим Brain, без paid calls.

### W2 — детерминированный диспетчер и план действий

- Приоритеты: scoped Stop/cancel → ожидаемый валидный слот → активное медиа → полные шаблоны/эллипсисы → ограниченный compound plan → optional semantic/разговор.
- Сделать escape из pending, корректный возврат погодного контекста, explicit ambiguity и unavailable.
- Реализовать ограниченный составной разбор с сохранением spans и preflight всего плана. Не разбивать слепо по союзам и не выполнять первое действие при неразобранном хвосте.
- Общий executor/arbiter с устойчивыми operation/action IDs, защитой replay и сохранением повторных намеренных действий.
- Pure conversation route минует semantic classifier, когда разбор не нужен. Task-like unknown не запускает платный fallback из-за ошибки локального навыка.
- Семантический plugin без разрешённого провайдера выключен; ошибки JSON/timeout → уточнение/честный отказ, не действие. Не устанавливать новую модель ночью.
- HassIL сравнить на малом локальном наборе только если это ускоряет задачу. При несовместимости оставить рабочие полные шаблоны, не делать migration самоцелью.

**Выход:** реальный детерминированный маршрут текущих инструментов и сохранённые native B/C callbacks.

### W3 — погодный помощник и таймеры

- Подключить существующий погодный adapter, нормализацию единиц/периодов/timezone и formatter без обязательной LLM.
- Реализовать текущее/завтра/доступный день/выходные/смену места/контекстные продолжения; rain window и зонтик только при достаточных данных.
- Речь с округлением/склонениями, экран с точными значениями; не путать максимум дня, текущую температуру и вероятность осадков.
- На weather HTTP error — честный fallback/cache age; не открывать B/C автоматически.
- Таймеры используют реальное существующее состояние, идемпотентность и renderer. После изменения темы отсчёт остаётся согласованным.
- Проверить связку вопрос → action result → AnswerEnvelope → renderer. Текст «готово» только после success.
- Разрешён небольшой read-only smoke существующей Open-Meteo интеграции без новых подписок; тестовые запросы ограничить, координаты дома/ответы не публиковать. Основной suite использует публичные синтетические fixtures.

**Выход:** первый полноценный web-путь бытовых задач, а не mock-имитация.

### W4 — Voice Library и рассказчик

- Инвентаризировать 100 существующих клипов, не пересоздавать их.
- Создать каталог и manifest фиксированных/динамических реплик, safe cache keys, dry-run generator, валидатор и pending-generation список. Не синтезировать платно автоматически.
- Текущий speech formatter и TTS использовать через общий presentation adapter. Кеширование не подменяет свежие данные.
- Реализовать browser storyteller state machine: queue, play, pause, resume, stop, bounded prefetch, acknowledged position и handover context.
- Подключить уже разрешённые text/TTS providers для ручного режима; неизвестные/неразрешённые adapters отображают unavailable. Не выдумывать генерацию истории.
- Проверить настоящий browser audio graph на явно обозначенном тестовом материале и отсутствие повторного воспроизведения late chunks.
- Готовый рассказ без модели работает как player; новая история при закрытом бюджете честно не генерируется.

**Выход:** общий реестр озвучивания и функционирующий плеер; готовность коммерческого голоса отдельно не заявляется.

### W5 — интеграция веб-устройства и переходов

- Добавить owner-only `/device-next` на прежнем приватном HTTPS, используя тот же Brain и круглый renderer. Если маршрут конфликтует, выбрать соседний и указать его точно.
- Пользовательский экран: Start/PTT, Stop, Mic/mute, честные состояния, виджеты, доступный способ ввода текста и понятные ошибки. Диагностический drawer показывает маршрут/источник/лимит без prompts и secrets.
- Переключатель Hybrid/Direct B/Direct C виден только в разрешённом owner scope. Все права проверяются сервером. Открытие страницы не создаёт provider session.
- B handover: правильный текстовый input и audio output contract; отдельные тесты формата. C handover: готовность подтверждается отдельно; не имитировать seamless ответ.
- Не менять старые `/device`, `/demo2`, аппаратный C default и исходные аудионастройки. Новый router включён только в web preview.
- B listening bounds, Tap-to-Finish, no infinite TV loops, playback ACK и stale-event tests. Сохранять текущую touch/mute политику.
- Проверить мобильный viewport, iPhone-safe layout, autoplay restrictions. Desktop test не объявлять Safari hardware PASS.

**Выход:** интегрированный кандидат, который Owner может открыть одним URL.

### W6 — бесплатный QA и независимый разбор

- Выполнить [ACCEPTANCE.md](ACCEPTANCE.md): 150 базовых текстовых кейсов плюс критические регрессии, server/JS/browser/integration checks.
- Дважды проверить пути no-paid-egress: бытовые requests и page load не создают B/C/LLM calls. STT/TTS usage проверяется отдельно.
- Реальные private endpoints проверить без создания model sessions. Synthetic tests не расходуют ручные grants.
- Дать Gemini/независимому review только diff и evidence, отдельный checkout. Если reviewer недоступен, провести self-review и явно записать отсутствие независимой проверки; не ждать Owner.
- Исправить introduced P0/P1 defects, повторить затронутые тесты. Не бесконечно полировать косметику при незавершённом сквозном пути.

**Выход:** отчёт с командами, exit codes, версиями и точной границей evidence.

### W7 — безопасная публикация веб-кандидата

- Повторно проверить single-writer ownership, активные обращения и локальные медиа-сессии. Наличие ledger unknown C не подделывать; отдельно убедиться, что локальный ресурс не занят.
- При active_turns/media > 0 не убивать разговор. Отложить только deployment, остальные артефакты завершить. Не запускать новый scheduler ради ожидания.
- Предпочесть additive frontend/feature flag на текущем сервисе. Если нужен перезапуск GoBot backend: backup, runtime SHA, rollback bundle, no active requests, один контролируемый restart. Не трогать другие сервисы/LiveKit без конкретной необходимости.
- Не запускать второй Brain на той же production SQLite и не публиковать новый внешний listener. Тестовая БД для suite не является production duplication.
- Smoke: health, auth, device-next HTTP, assets, typed deterministic requests, нулевые paid create. На failure сразу вернуть последний рабочий runtime/config, сохранить диагностику и закончить отчёт о rollback.
- Если deployment не разрешён фактической средой или небезопасен, оставить tested build + точную штатную команду запуска. Нельзя написать «уже доступно», когда это только build artifact.

**Выход:** runtime proof/URL либо честный deployment blocker с готовым кандидатом.

### W8 — аппаратная подготовка и handoff

- Сверить capabilities 0.4.3: stream IDs, continuous WSS, stop/drain ACK. Не предполагать, что на плате уже есть точная позиция сегмента.
- Подготовить versioned compatible protocol extension и минимальный firmware patch в отдельной ветке/каталоге.
- Если расширение ACK не поддерживается старым firmware: не синтезировать ACK на сервере; gated feature или подготовленный patch, downgrade явно описан.
- Собрать candidate на закреплённом существующем toolchain/build host, если доступно в текущих правах. Проверить memory/partition budget и SHA; не обновлять глобальный SDK.
- Нет flash, OTA, стирания NVS, wake enable или платных аппаратных тестов. Build PASS не есть hardware PASS.
- Оформить утренний отчёт, CURRENT_STATUS с явной новой секцией и draft PR. Историческую матрицу не переписывать как будто все старые проверки повторены.

## 3. Управление блокерами

Карантин C не блокирует W1–W4. Отсутствие paid grant не блокирует контракты, UI и бесплатные тесты. Неизвестный TTS contract блокирует лишь соответствующую real-voice отметку. Недоступный build host блокирует только бинарник; подготовить patch/manifest/instructions. Отсутствие Gemini блокирует только независимый review.

После двух неудачных попыток одного и того же внешнего dependency/install/build setup с одинаковой причиной прекратить цикл, записать blocker и выбрать разрешённый простой путь. Это ограничение повторения инфраструктурной попытки, не лимит числа исправляемых программных ошибок. Не тратить ночь на подключение нового оркестратора или замену рабочего стека.

## 4. Итоговые артефакты

В существующих docs/tests conventions сохранить:

- runtime/baseline manifest и изменённые флаги;
- source diff + небольшие логические commits;
- evaluation dataset и результат по категориям;
- browser screenshots, evidence событий playback и тестовый сетевой trace без secrets;
- voice catalogue + ready/missing inventory и dry-run cost estimate с неизвестными значениями, не выдуманными ценами;
- weather fixtures/formatter cases;
- firmware patch/build manifest/непроверенные возможности;
- MORNING_REPORT с точным URL, четырьмя–шестью ручными сценариями, статусом C/B/гибрида, rollback и оставшимися задачами.

Время «завтра утром» — момент проверки Owner, не доказательство исполнения и не повод подделывать готовность. Финальный статус одной задачи не скрывает незавершённость другой.

Дата проверки: 2026-11-16 (America/Sao_Paulo). Статус: **публичный код-снимок, не релиз и не развертывание**.

## Почему `master` отстаёт
GoBot разрабатывался на Windows PLAN в отдельных локальных ветках и worktree; отправка в публичный GitHub выполнялась **выборочно, после санитарной проверки**. Поэтому `master` (`fcbfeaa` на момент проверки) не соответствует самой новой работе PLAN и не должен приниматься за источник текущей установленной прошивки. Нельзя откатывать PLAN к `master` или `a31674e`.

## Публичность и границы
- Репозиторий **public**. При этой инспекции `gitleaks 8.30.1 git --log-opts=--all --redact=100` на PLAN вернул код **0**; отдельная проверка расширений в текущем Git tree не выявила отслеживаемых `.env/.pem/.key/.sqlite/.db/.wav/.bin`.
- Это не доказательство отсутствия любых личных данных. Запрещено публиковать `data/`, runtime конфигурации, секреты, NVS/бинарники платы, аудиозаписи, персональные модели, сырые диагностические логи и аккаунтные токены.
- Не изменять удалённый `master` автоматически, не переключать production, не сбрасывать финансовые ledgers и не обходить сроки удаления приватных данных.

## Как поддерживать синхронизацию дальше
1. HOST-A и HOST-B делают **отдельные коммиты в своих worktree**, каждый прогоняет бесплатные тесты и проверку файлов/секретов.
2. После этого каждый публикует очищенную ветку в GitHub с точной ссылкой на локальный commit/tree; никакого `--force`, никакого переписывания общей ветки.
3. Дальнейшее продвижение в `master` — отдельный этап ревью/интеграции. До него **текущие опубликованные снимки нужно смотреть по указанным веткам, а не по `master`**.
4. Заявления `SOURCE_IMPLEMENTED`, `FREE_TESTED`, `BUILT`, `INSTALLED`, `HUMAN_ACCEPTED` вести раздельно. Опубликованный код не подтверждает физическую приёмку.

# Multimodal response planning — 10 ноября 2026

## Экран при отсутствии изображения

Карта понятий больше не является пользовательским визуалом. Новые ответы её не создают. Старые сохранённые карты пропускаются сервером и обоими рендерами. При отсутствии подходящей иллюстрации остаётся лицо. Настоящие учебные схемы, таймеры и другие предметные виджеты работают по прежнему контракту.

Вопросы о персонажах мультфильмов могут не содержать конкретного имени. Для них локальный обработчик читает завершённые предложения обычного ответа и выделяет упоминания вида «динозавр Герти», «кот Феликс». Авторов мультфильмов такой шаблон не выбирает. В одном ответе допускаются до трёх изображений через прежний VisualService, без дополнительного модельного вызова. Изображения поступают по готовности, не ожидая конца текста. Панель показывает карточки, круглый экран переключает полученные изображения каждые пять секунд. При новом вопросе очередь очищается.

Это ограниченный обработчик названных персонажей, а не универсальный NER. Объект с неподдержанной формулировкой может остаться без иллюстрации. Для Фантоша проверена связь с «Фантасмагорией». Используется растровый кадр от Commons, видеофайл не загружается. Public domain из метаданных Commons поддерживается и при отсутствии отдельного LicenseUrl. В карточке сохраняется ссылка на первоисточник.

Реальные бесплатные источники проверены для Герти (историческая афиша), Фантоша (кадр фильма) и Феликса (рисунок). Качество исторических утверждений основного ответа в этих проверках не оценивалось. Новых CLI/STT/TTS-запросов не было.

## Текущий путь от вопроса до иллюстрации

После финального STT сервер выделяет публичный объект и начинает загрузку. Gateway учитывает настройки экрана и выбранный режим. Для введённого текста Brain начинает ту же работу после допуска маршрута, до первого чтения потока CLI. Antigravity и Codex возвращают обычный текст. Служебная разметка прежних версий фильтруется, если случайно попадёт в реплику.

Экстрактор использует русскую морфологию, локальный словарь и несколько правил разрешения омонимии. Для вопроса о грибах-лисичках поисковый термин — статья о роде грибов. Страна не попадает в запрос к фотобанку. Неоднозначные существительные, конкурирующие объекты и личные запросы могут остаться без внешнего поиска. В этом случае остаётся лицо GoBot. При отключённых иллюстрациях действуют настройки экрана.

Источник и реплика проверяются независимо. В смешанном режиме Wikimedia получает фору 350 мс для разрешения статьи и её лицензированного файла. Если результат ещё не готов, Openverse работает параллельно. Для автоматического показа совпадения слова в длинном заголовке снимка недостаточно. Подготовленный JPEG остаётся кандидатом, пока фрагмент ответа не подтвердит тему. Для поддержанных уточнений вида возможен один новый поиск. Отмена завершает работу текущего вопроса. Загрузка фото не останавливает передачу текста и предложений в TTS.

Передача фоновой загрузки из STT ограничена текущим владельцем, идентификатором фразы и хешем финального текста. В памяти сервера допускаются до восьми незабранных задач на 25 секунд. Промежуточные транскрипции не запускают поиск. История того же владельца показывает сохранённые фотографии и схемы. Для старых ответов с отклонённым планом история может восстановить иллюстрацию из локального кэша. Просмотр истории не обращается к фотобанкам и не меняет исходный диалог.

Телеметрия разделяет начало поиска, готовность файла, подтверждение сущности и показ на клиенте. Метки разных часов нельзя вычитать друг из друга. На панели метка показа означает загруженное изображение в DOM после кадра отрисовки, на круглом дисплее — вызов рисования на canvas. Реальная видимость для человека и слышимый отклик требуют отдельного испытания на телефоне.

## Схемы из Wikimedia

После ошибки на вопросе об устройстве эндокринной системы исправлен путь SVG-источников. Commons imageinfo может вернуть SVG как оригинал и готовый PNG thumbnail. GoBot загружает только растровую копию с разрешённого Commons thumbnail URL. Ответ HTTP всё равно проходит проверку MIME, размера и декодирование Pillow. SVG-код на сервере или клиенте не исполняется.

Прозрачный фон растровых схем компонуется на белый фон, чтобы чёрные подписи оставались читаемыми. Версия нормализации увеличена. Если поиск завершился ошибкой после подтверждения темы, на экране остаётся лицо GoBot. Просмотр старой истории может восстановить фото из кэша после ошибки поиска без изменения исходных сообщений.

Проверена настоящая схема [Endocrine English](https://commons.wikimedia.org/wiki/File:Endocrine_English.svg), OpenStax, Tomáš Kebert, umimeto.org, CC BY-SA 4.0. Подписи исходника английские. Повтор сохранённого текста через Service в изолированной базе показал схему после первого предложения за 125 мс с прогретым кэшем. Это replay без CLI и STT/TTS. Полный голосовой путь на iPhone этим замером не проверен.

## Предыдущая версия с планом внутри ответа

Новый реальный результат: real-visual-checks.json. Три разрешённых Flash turns через
настоящий Browser Client: белый гриб показан; затем обнаружена и исправлена форма
названия «солнечный аратинга»; повторная проба показала попугая. DOM complete и
naturalWidth подтвердили загрузку обеих фотографий. 575 pytest; native 240×240
raster harness также прошёл. Остальные сценарии этим малым набором не валидированы;
реальный iPhone и STT/TTS в этих проверках не использовались.

После реальной пользовательской ошибки «белый гриб еловый → image_not_found»
добавлен entity-aware путь: PageImages RU/EN Wikipedia → точное имя Commons-файла →
imageinfo/extmetadata → прежние проверки лицензии/MIME/DNS и ImageCache. Служебный
план модели в исходном запросе был корректным; фильтр русской строки против
латинской подписи оказался недостаточен. Новые варианты не требуют ручной пары
названий в словаре. Источник статьи сохраняется в query cache отдельно от самого
asset, чтобы один общий файл не переносил утверждение о разновидности между запросами.

Дизамбигуация и несвязанные заголовки отбрасываются до загрузки: «Мухомор вонючий»
не подходит для «белый гриб». Если заголовок покрывает лишь общий объект, применяется
topic_overview/approximate_match, подпись «обзор» и явное отсутствие подтверждения
конкретной разновидности. Это не инструмент определения съедобности по фотографии.
На круглом экране краткая обзорная подпись сохраняет это различие. 572 pytest и
Node raster harness прошли до новых реальных модельных проб.

Для обычного ответа Antigravity/Codex общий runtime теперь запрашивает компактный
`<gobot_visual_v1>` JSON после первого предложения с выбранным объектом. Модель
выбирает photo/diagram/avatar по вопросу и планируемому ответу. Subject сохраняет
конкретный вид/модификаторы, не сокращается до случайного одного слова. Второго
модельного вызова нет. Платная генерация изображений не включается этим протоколом.

Brain инкрементально удаляет служебный блок до display, Speech Formatter, TTS и
сохранения финального ответа. Строгая схема, лимит 1024 символа, один блок/одна
визуальная задача. Неполный/невалидный блок не озвучивается. Объект должен уже
встречаться в выданном ответе целыми словами; личные запросы и очевидные
междоменные противоречия отклоняются. Это проверки согласованности, не доказательство
истинности модели или независимый универсальный semantic judge.

Фото проходит существующий VisualService/cache с дополнительным сравнением имени
и метаданных кандидата. Словарь RU/EN — вспомогательный нормализатор, не выбирает
смысл ответа. При недоступном Openverse возможен существующий Commons backend
с публичным User-Agent проекта и прежними DNS/URL/MIME/license/rate ограничениями.
Первый поиск ограничен 3 с; нет ожидания фото перед первой фразой TTS. Таймеры,
явные изображения и подготовленные локальные схемы сохраняют детерминированный путь.

Проверено 563 pytest, включая fragmented markup, две CLI-маршрутизации на fixtures,
первое аудио до окончания поиска, отмену, cache/dedupe, нерелевантного кандидата,
Commons fallback и точную очистку трёх UTM-полей imageinfo. Реально получена и
осмотрена фотография солнечной аратинги; device JPEG 240×240, 13713 байт, CC BY-SA 3.0.
См. answer-visual-integration.json. Решение модели в этой интеграции задано фикстурой:
на том этапе новых CLI/OpenAI-вызовов не было. После него выполнены разрешённые
реальные CLI/browser пробы выше. Физический iPhone пока не подтверждён.
Старые пользовательские ответы не переписывались.

## Существующие стратегии

PresentationPlanner вызывается для каждого ответа; решения отделены от Smart Router,
провайдера ответа и HTML. Plan включает visual_needed/priority/type/strategy/query/template,
origin и speech_policy. Дополнительного модельного классификатора нет. Политика:
services/brain/presentation-policy.json. Явные изображения обязательны; полезное
автоматическое сопровождение включено; smalltalk без дополнительной картинки.

Retrieve: существующие Openverse/Commons и локальный media cache. Generate: восемь локальных
процедурных учебных иллюстраций — лунный кратер, Земля–Луна, солнечное затмение,
вулкан, томатный куст, сравнение форм томатов, условные силуэты собак, Млечный Путь.
Это не нейросетевая генерация и не фотографии. Render_local: реальные таймеры,
системный статус и доступность погодного/музыкального источника. Платного image
провайдера нет; никакие credits не используются.

Неявная иллюстрация готовится параллельно тексту, отдельный visual_response SSE.
Ограниченный merge держит один ожидающий text delta и одну visual task. Готовая
фраза передаётся TTS сразу; даже ответ без финальной пунктуации сбрасывается в
speech до ожидания картинки. Ошибка необязательного визуала не ломает ответ и
не вызывает дорогой fallback. Timeout auto-визуала 8 с, cancel закрывает обе задачи.
Внешние проверки/высокий риск и приватная память имеют приоритет. Фото не является
доказательством ответа. Для обычного ответа speech следует содержанию модели через
Speech Formatter; отдельной большой модели для свободного пересказа нет.

Browser и compact ESP32 DTO сохраняют synthetic/strategy, source/credits и device
240×240 JPEG. Схемы условные, не в масштабе. Native LVGL/плата не проверены.
Браузерные инструменты не предоставили браузер, Safari rendering не подтверждён.

Offline tests используют fake text/audio и отдельные базы. Настоящий private HTTPS:
multimodal-e2e.json — три implicit запроса в явно указанном Mock, реальные локальные
JPEG; текст этих проб диагностический, не ответ реальной LLM. Владелец может
проверить AUTO сам; новые платные модельные сравнительные пробы не запускались.

Ограничения: локальные схемы ограничены шаблонами; новый модельный выбор визуала
требует проверки соблюдения контракта реальными CLI. Генерация по произвольному prompt не реализована.
Точность general image retrieval не подтверждена: проба «телескоп» нашла спектральную
диаграмму NASA вместо фотографии прибора. Успешная загрузка не равна релевантности.
Это ограничение записано явно, не считается пройденным качественным сценарием.

## Русскоязычный image query

Локальная FreeDict/WikDict rus-eng 2025.11.23: 33717 noun/adjective headwords после
отбора из 42600; 2.28 MB JSON. Существующий pymorphy3 разбирает падежи/числа.
Один смысл → английский поисковый термин; неоднозначность/неизвестный модификатор
не отбрасываются ради количества результатов. Не более двух metadata поисков;
если английский пуст, пробуется исходный. Нет платного переводчика/CLI вызова.
Пончик загружен и просмотрен: Flickr 24311648@N00/6142660833, Jelly Modern Doughnuts.

Воспроизведение: .venv/Scripts/python.exe scripts/prepare_visual_dictionary.py.
Фиксированные release URL/SHA512 в скрипте. CC BY-SA 3.0: Karl Bartel, WikDict,
Wiktionary contributors, DBnary, FreeDict. Происхождение и изменения сохранены в
vendor/dictionaries/rus-eng.json; оригинал и COPYING рядом. Данные не являются
кодом GoBot; никаких глобальных пакетов/версий не менялось.

Источники: https://freedict.org/documentation/ и заголовок закреплённой TEI;
https://docs.openverse.org/api/reference/search_algorithm.html. Wikidata query
вернул HTTP 403; новый runtime доступ к нему не добавлялся.

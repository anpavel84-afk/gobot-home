# Политика контекста GoBot — 10 ноября 2026

Проверка жалобы на несвязное продолжение: журнал ContextPacket подтвердил наличие
обоих сообщений предыдущего обмена и outcome=continue. Потеря этого обмена при
сборке контекста не обнаружена; это не доказывает, что модель использовала его
правильно. В общие инструкции добавлено требование сопоставлять новое наблюдение
с предыдущим ответом, явно разбирать расхождение и не считать прежний ответ модели
проверенным источником. ContextPacket теперь содержит серверную current_date_utc,
отдельно учтённую в бюджете; местная дата/местоположение пользователя из неё
не выводятся. Архивные даты не подменяют часы сервера. Новый prompt проверен на
synthetic history → ContextBuilder → mocked subprocess stdin, без платных вызовов.
Качество реального следующего ответа требует отдельного наблюдения; тесты правил
и передачи данных не являются проверкой понимания модели.

Архив хранится в GoBot. Модель получает отдельный ограниченный ContextPacket.
Измеренный размер пакета не является полным входом CLI и не является счётом за API.

## Аудит пути до изменения

Browser отправлял текст и conversation_id через приватный HTTPS gateway. Gateway
назначал device_id по Tailscale peer / PIN-профилю. Brain сохранял пользовательское
сообщение, загружал 12 последних сообщений этой conversation, extractive summary из
последних шести сообщений, первый вопрос и consent-факты. Эти данные частично
дублировали друг друга. В промежуточной реализации ContextManager сокращал их по
символам; это не был токеновый бюджет.

SQLite на момент аудита: 198 turns, из них 174 mock и 10 bridge:mock; остальные
попытки включали реальные CLI и неуспешные обращения. Групп дублирования
conversation_id + turn_id + role: **0**. Одинаковые mock-ответы объясняются постоянным
текстом фикстуры, а не доказанной повторной доставкой аудио. Legacy summaries могли
содержать mock. Исходные записи сохранены, диагностические исключены из retrieval.

Codex уже создавал новый ephemeral thread/start на каждый turn. Antigravity запускал
новый процесс, одно user-событие, без continue/resume. Удвоения накопленного provider
thread и полной SQLite-истории в этом пути не обнаружено. Инженерный Codex-чат не
используется как GoBot conversation.

## Путь после изменения

Browser → HTTPS gateway (проверка peer/Origin/PIN) → Brain → scoped TopicRouter →
ContextBuilder → подписанный loopback Bridge → новый контекст Codex / Antigravity.

На каждом новом сохранённом turn TopicRouter учитывает реплики обеих сторон.
Отсутствие общих слов само по себе больше не сбрасывает тему. Предварительная
эвристика передаётся как dialogue_state; смысл реплики оценивает отвечающая модель
по диалогу, без отдельного LLM-классификатора.

Рабочее окно — до трёх последних завершённых production-обменов той же conversation
и owner, даже при предполагаемой смене темы. Оно объединяется с сообщениями темы
по source ID и в хронологическом порядке. Целые пары вопрос/ответ сохраняются в
общем recent budget 1500 токенов; слишком большой обмен явно отмечается
recent_exchange_over_budget. Явное new_topic / «новая тема» задаёт границу окна
и на следующих ходах. Diagnostic-сброс не влияет на production. Другой owner
или conversation_id не получает это окно. Temporary остаётся RAM-only без archive search.

В packet входят runtime-правила, текущий вопрос, целые последние сообщения активной
темы и рабочее окно, непересекающийся summary, явно разрешённые факты и до пяти архивных фрагментов.
Пустые разделы не сериализуются. Один source message не дублируется в последних
репликах, summary и retrieval. История другой темы не добавляется просто для заполнения.

`services/brain/context-policy.json`: target 3600, hard max 6000; recent 1500,
summary 500, facts 300, retrieved 1200 токенов. Это верхние границы. Текущий вопрос и
runtime-ограничения не обрезаются; превышение возвращает явную ошибку. Для явно
запрошенного `context_detail: detailed` отдельный max 12000 / target 7500.

cl100k_base через tiktoken считает точно сериализованный GoBot prompt, включая
нейтрализацию @file. Для других tokenizer CLI это **оценка**, не фактический usage.
При недоступности tokenizer используется обозначенная UTF-8 оценка. Файл tokenizer
кешируется только в run/tiktoken. Установки глобальных пакетов не требуются.

## Контекст, добавляемый CLI

Codex 0.159.2: project_doc_max_bytes=0, MCP очищен, skills/apps/plugins отключены,
shell/apply_patch отсутствуют в text-only catalog. Offline локальный HTTP-аудит
показал tools=[]. Сохраняется нативный префикс модели/CLI; его размер не установлен.

Antigravity 1.5.3: strict deny для файлов, команд, URL и MCP; historySize=0,
без resume; отдельный cwd и child home. Запрет инструментов не доказывает отсутствие
их schemas и native instructions во входных токенах. Дополнительные токены не
объявляются нулевыми. Это ограничения официального CLI, не универсальная OS-песочница.

Из Codex принимается thread/tokenUsage/updated.last, из AGY — result.usage, только
числовые allowlisted поля. При отсутствии события показывается «недоступно».
provider_sessions хранит фактический Codex thread ID, если он пришёл, либо NULL.
AGY session ID пока не извлекается. CLI quotas не пересчитываются в выдуманные доллары.

## Обслуживание памяти и удаление

Summary — локальные атрибутированные выдержки, по новым сообщениям изменённой темы,
без модельного вызова. Очередь ограничена 32 темами, одна локальная задача за раз.
Версия, source IDs, boundary и generation сохраняются транзакционно. Решения из
предложений модели автоматически не извлекаются. Полноценное смысловое summary
цель/условия/решения ещё не реализовано.

Source notes теперь сохраняют исходную пользовательскую постановку и несколько
последних выдержек в пределах 500 токенов. Из summary удаляются отдельные цитаты,
уже переданные дословно, а не весь итог из-за одного пересечения. Это частичные
выдержки, не полный смысловой конспект: решения/открытые вопросы не выдумываются.

Практики сверены с первичными источниками 10 ноября 2026:
[LangGraph memory](https://docs.langchain.com/oss/python/langgraph/add-memory)
разделяет состояние разговора и долгосрочную память;
[Semantic Kernel](https://learn.microsoft.com/en-us/semantic-kernel/concepts/ai-services/chat-completion/chat-history)
описывает token/count reducers и сжатие;
[Anthropic](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)
описывает compaction и сохранение существенных решений/нерешённых задач.
Применены окно + бюджет + source notes в существующем GoBot, без новой платформы.
Полноценный семантический конспект остаётся незавершённой частью: для него ещё нужны
контроль полноты, явная модель затрат и реальные проверки качества.

Платная extraction/summary/classification обработка выключена. Резервирование её
бюджета реализовано: ≤10% фактически учтённых дневных provider tokens и абсолютный
предел 2000; без usage разрешение равно нулю. Каждая попытка резервируется отдельно.
Никакого фонового платного агента нет. Текущий расход вспомогательных моделей: 0.

«Не запоминать» исключает новые тексты из SQLite, FTS, summaries и содержательных
диагностик. Только ограниченная оперативная память до часа / завершения процесса.
Старый архив это не удаляет. Provider retention определяется отдельно провайдером.
Удаление разговора каскадно очищает сообщения, FTS, context_runs, sessions, speech,
производные summaries и задания; generation не позволяет очереди воскресить данные.
Резервные SQLite-копии не изменяются автоматически и могут содержать удалённые тексты.
